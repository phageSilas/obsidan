## 摘要

当前后端**不能直接满足**你要做的“管理者工资条管理界面”需求，原因不是前端问题，而是现有工资条接口本质上还是**员工自助查看接口**，不是管理端接口。

已确认现状：

- 现有接口：
    - `GET /api/v1/salary/payslips`
    - `POST /api/v1/salary/payslip/verify`
    - `GET /api/v1/salary/payslip/{id}`
- 这些接口当前逻辑都绑定 `getCurrentEmployeeId()`，也就是：
    - 只能查**当前登录员工本人**的工资条
    - 明细详情会校验 `item.employeeId == 当前登录员工`
- 因此它**不能**支持你要的管理端能力：
    - 按员工姓名/工号查询
    - 按部门分页查询
    - 管理者查看任意员工工资条
    - 管理者“已查看 / 未查看 / 待发布”状态管理

密码二次验证方面：

- **只有密码验证、没有短信验证**这一点，当前后端是满足的
- 但“管理者本次登录只验证一次，之后查看任意员工工资条都不再重复验证”这一点，**当前后端也不满足**
- 因为当前验证缓存 key 是：
    - `salary:payslip:verify:{employeeId}:{month}`
- 且这里的 `employeeId` 取的是**当前登录人绑定员工 ID**
- 同时详情接口还要求工资条记录必须属于当前登录员工本人
- 所以这套校验机制是面向“员工看自己工资条”的，不是“管理者看别人工资条”的

## 后端现状判断

### 1. 现有接口能满足的部分

- 密码二次验证：
    - `POST /api/v1/salary/payslip/verify`
    - 请求体只有：
        - `month`
        - `password`
    - 这一点符合“只做密码验证、不做短信验证”
- 工资条详情展示字段：
    - `SalaryPayslipDetailVO extends SalaryBatchItemVO`
    - 已有收入、扣除、实发等细项
    - 足够支撑原型图里的工资条详情弹窗

### 2. 现有接口不能满足的部分

- `GET /api/v1/salary/payslips`
    - 当前只支持 `month`
    - 返回的是**当前员工本人**工资条列表
    - 没有分页
    - 没有姓名/工号/部门筛选
    - 没有管理端“查看状态/发布状态”
- `GET /api/v1/salary/payslip/{id}`
    - 当前强校验：
        - `item.employeeId == 当前登录员工`
    - 所以管理者无法查看他人工资条
- `POST /api/v1/salary/payslip/verify`
    - 当前验证成功后只写：
        - `salary:payslip:verify:{当前员工ID}:{month}`
    - 不具备“管理者登录后一次验证，整场会话查看多人工资条都免再次验证”的能力

## 后端需要补的接口/改造

### 1. 新增管理端工资条分页接口

建议新增：

- `GET /api/v1/salary/manage/payslips`

建议参数：

- `keyword?: string`
    - 员工姓名 / 工号模糊查询
- `month?: string`
    - `yyyy-MM`
- `deptId?: number`
- `viewStatus?: string`
    - 建议枚举：
        - `VIEWED`
        - `UNVIEWED`
        - `UNPUBLISHED`
- `pageNum?: number`
- `pageSize?: number`

建议返回字段：

- `id`
- `employeeId`
- `employeeName`
- `employeeNo`
- `deptId`
- `deptName`
- `salaryMonth`
- `grossSalary`
- `deductionTotal`
- `netSalary`
- `batchStatus`
- `viewStatus`
- `verified`
- `publishStatus` 或直接由 `batchStatus` 映射也可

说明：

- 这才是前端“工资条管理界面”的主列表接口
- 权限只开放给：
    - `FINANCE / HR / HR_TEST / ADMIN / ROLE_ADMIN`

### 2. 新增管理端工资条详情接口

建议新增：

- `GET /api/v1/salary/manage/payslip/{id}`

用途：

- 管理者查看任意员工工资条详情
- 返回结构可直接复用现有 `SalaryPayslipDetailVO`
- 但不要再校验“必须是当前员工本人”

### 3. 新增管理端二次验证接口

建议新增：

- `POST /api/v1/salary/manage/payslip/verify`

建议请求体：

- `password: string`

说明：

- 既然你要求“管理者本次登录期间只验证一次”
- 那么这个验证不应该再按 `employeeId + month` 维度缓存
- 应该改成“当前管理用户会话级”的验证

建议缓存 key：

- `salary:manage:payslip:verify:{userId}:{loginToken}`  
    或至少：
- `salary:manage:payslip:verify:{userId}`

建议过期时间：

- 与本次登录会话一致
- 或 30 分钟 / 2 小时均可，但前后端需口径一致

### 4. 管理端详情接口的验证规则

建议管理端详情接口逻辑改为：

- 判断当前登录用户角色是否属于管理端可见角色
- 再检查是否已完成本次登录会话级二次验证
- 验证通过后，本次登录期间查看其他员工工资条**不再重复验证**

这样才能满足你要求的：

- 管理者只验证一次密码
- 本次登录期间再次查看员工工资条不再重复验证

## 前端实现结论

### 当前后端下，前端能做的

- 可以先做工资条页面外壳和原型图 UI
- 但真实数据链路只能做“当前员工自己看自己”
- 不能做管理端工资条管理页

### 在后端补齐后，前端可以完整实现

补齐上述 3 个管理端接口后，前端就能稳定实现：

- 只有财务 / HR / 管理员可见的工资条管理页
- 按姓名/工号、月份、部门分页查询
- 按“已查看 / 未查看 / 待发布”状态筛选
- 点击查看时弹密码验证框
- 本次登录内只验证一次
- 后续查看任意员工工资条直接打开详情弹窗

## 测试场景

- 管理者进入工资条页后，可分页看到所有可管理员工的工资条记录。
- 可按员工姓名/工号模糊查询。
- 可按月份筛选。
- 可按部门筛选。
- 可按查看/发布状态筛选。
- 首次点击“查看”时要求密码验证。
- 验证成功后，本次登录期间再次查看其他员工工资条不再重复验证。
- 普通员工不可进入该管理页。
- 管理者可查看任意有权限员工的工资条详情，而不是只看自己。

## 假设与默认选择

- “状态”按你的描述拆成管理端可理解的三类：
    - 已查看
    - 未查看
    - 待发布
- 本次登录期间“一次验证即可”默认按**服务端缓存会话级验证态**实现，不依赖纯前端内存态。
- 工资条详情结构可复用现有 `SalaryPayslipDetailVO`，不强制新建详情 VO。
