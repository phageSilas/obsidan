
# 技术总结：前端界面“每次点开”自动调接口，实现数据随用户持久化

## 一、核心概念澄清（消除认知误区）

要实现“用户操作数据持久化显示”，必须严格区分两种“持久化”：

1. **后端数据库持久化（根本）**：业务数据存储在后端数据库。**项目重启、用户重新登录都不会导致数据丢失**，只要登录同一账号，接口返回的就是该用户的完整历史数据。
2. **前端存储持久化（辅助）**：`localStorage` / `sessionStorage` 仅用于存放身份令牌（Token）或作为离线兜底缓存。**不能作为主要数据源**，否则换设备或清缓存会导致数据“消失”。

**结论**：只要每次进入页面都**强制调用后端接口**拉取最新数据，就能保证显示的是当前用户最准确、完整的持久化数据。

## 二、React + TypeScript 具体实现方案

### 1. 定义强类型（确保类型安全）

```typescript
// 定义数据结构
export interface UserData {
  id: string;
  name: string;
  value: number;
}

// 封装API请求（携带Token + 防缓存）
import axios from 'axios';
export const fetchUserData = async (): Promise<UserData[]> => {
  const { data } = await axios.get<UserData[]>('/api/data', {
    headers: { Authorization: `Bearer ${localStorage.getItem('token')}` },
    params: { _t: Date.now() } // 时间戳防止浏览器HTTP缓存
  });
  return data;
};
```

### 2. 监听“每次点开”的三种场景

| 场景 | 技术方案 | 代码关键点 |
| :--- | :--- | :--- |
| **浏览器刷新 / 新开标签页** | `useEffect` 空依赖 `[]` | 组件挂载时自动触发。 |
| **SPA内部路由切换（最常用）** | 监听 `location.key` | `useEffect(() => { fetchData(); }, [location.key])`，路由变化必定重新请求。 |
| **从后台切回前台（切屏/切APP）** | 监听 `visibilitychange` 事件 | `document.visibilityState === 'visible'` 时重新调接口。 |

### 3. 核心逻辑代码（含竞态处理）

```tsx
import { useEffect, useState } from 'react';
import { useLocation } from 'react-router-dom';

const DataPage = () => {
  const location = useLocation();
  const [data, setData] = useState<UserData[]>([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const controller = new AbortController(); // 取消过期请求，防止竞态

    const loadData = async () => {
      setLoading(true);
      try {
        const res = await fetchUserData();
        setData(res);
      } catch (error) {
        if (!axios.isCancel(error)) {
          console.error('加载失败', error);
        }
      } finally {
        setLoading(false);
      }
    };

    loadData();
    return () => controller.abort(); // 组件卸载时取消请求
  }, [location.key]); // 依赖路由Key，保证切换页面必刷新

  // ... 渲染逻辑
};
```

### 4. 高级封装：自定义 Hook（`useRequest`）

将逻辑抽离为泛型Hook，便于全局复用，自动管理 `loading`、`error` 和请求触发。

```tsx
export function useRequest<T>(
  service: () => Promise<T>,
  deps: React.DependencyList = []
) {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState(false);
  
  useEffect(() => {
    setLoading(true);
    service().then(setData).finally(() => setLoading(false));
  }, deps);
  
  return { data, loading };
}

// 页面中使用
const { data, loading } = useRequest(fetchUserData, [location.key]);
```

## 三、疑难杂症解决：切到其他界面再返回，数据空白怎么办？

### 问题根源
- React SPA中，离开页面时组件**卸载**，`useState` 数据被销毁。
- 返回时组件**重新挂载**，若请求失败（或请求过程中 `setData(null)` 提前置空），界面即显示空白。
- **这并非 HTTP 缓存问题**，而是组件生命周期与状态管理策略问题。

### 解决方案（三层保险）

1. **监听路由变化**：务必使用 `[location.key]` 作为 `useEffect` 依赖，确保返回必触发请求。
2. **请求失败时保留旧数据**（防止闪白）：
   ```tsx
   const fetchData = async () => {
     setLoading(true);
     // ❌ 不要写 setData(null) 
     try {
       const res = await api.get();
       setData(res);
     } catch {
       // 失败时保留旧 data，界面不会突然变空
     } finally {
       setLoading(false);
     }
   };
   ```
3. **SessionStorage 秒开兜底（提升体验）**：请求前先从 `sessionStorage` 读取缓存立即渲染，请求成功后再覆盖缓存和状态，实现“先看旧数据，再刷新成最新”。

## 四、最终核心法则

> **后端数据库存根本，路由监听保触发，请求失败不置空，强缓类型护周全。**

只要遵循上述法则，无论用户是**刷新页面、切换路由、重新登录还是服务器重启**，前端界面都能稳定、准确、完整地展示该用户对应的持久化数据。
