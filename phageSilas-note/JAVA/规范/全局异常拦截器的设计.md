## `GlobalExceptionHandler`类的作用是：
**把 Controller/Service 里抛出来的异常统一拦住，然后转换成统一返回体 `Result` 返回给前端**。

如果没有它，接口异常时前端可能收到 Spring Boot 默认错误：

```
{
  "timestamp": "...",
  "status": 500,
  "error": "Internal Server Error",
  "path": "/api/user"
}
```

有了它之后，你可以统一返回：

```
{
  "code": "A000401",
  "message": "用户未登录",
  "data": null
}
```

---

## **`@RestControllerAdvice` 是什么？**

它可以理解成：

```
@ControllerAdvice + @ResponseBody
```

也就是说，它会增强所有 Controller，并且方法返回值会自动序列化成 JSON。

典型写法：

```
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult()
                .getFieldErrors()
                .get(0)
                .getDefaultMessage();

        return Result.fail("A000400", message);
    }

    @ExceptionHandler(Throwable.class)
    public Result<Void> handleThrowable(Throwable ex) {
        log.error("系统异常", ex);
        return Result.fail("B000001", "系统执行出错");
    }
}
```

---

它的处理流程是这样的：

```
前端请求
  ↓
Controller
  ↓
Service 抛异常
  ↓
异常向上冒泡
  ↓
GlobalExceptionHandler 捕获
  ↓
转换成 Result
  ↓
返回 JSON 给前端
```

比如 Service 里：

```
public UserRespDTO getUser(Long id) {
    UserDO user = userMapper.selectById(id);
    if (user == null) {
        throw new BusinessException(ErrorCode.USER_NOT_FOUND);
    }
    return BeanUtil.toBean(user, UserRespDTO.class);
}
```

全局异常处理器捕获：

```
@ExceptionHandler(BusinessException.class)
public Result<Void> handleBusinessException(BusinessException ex) {
    return Result.fail(ex.getCode(), ex.getMessage());
}
```

最终前端收到：

```
{
  "code": "A000404",
  "message": "用户不存在",
  "data": null
}
```

---

`@ExceptionHandler` 是用来声明“这个方法处理哪种异常”。

比如：

```
@ExceptionHandler(BusinessException.class)
```

只处理业务异常。

```
@ExceptionHandler(MethodArgumentNotValidException.class)
```

处理参数校验异常，比如 `@Valid` 校验失败。

```
@ExceptionHandler(Throwable.class)
```

兜底处理所有没被前面捕获的异常。

一般顺序上你要设计这几类：

```
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    /**
     * 处理业务异常
     */
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    }

    /**
     * 处理参数校验异常
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult()
                .getFieldErrors()
                .stream()
                .findFirst()
                .map(FieldError::getDefaultMessage)
                .orElse("请求参数错误");

        return Result.fail("A000400", message);
    }

    /**
     * 处理未知异常
     */
    @ExceptionHandler(Throwable.class)
    public Result<Void> handleThrowable(Throwable ex) {
        log.error("未知异常", ex);
        return Result.fail("B000001", "系统繁忙，请稍后再试");
    }
}
```

---

为什么要全局异常处理？

因为不想每个 Controller 都这样写：

```
@GetMapping("/user/{id}")
public Result<UserRespDTO> getUser(@PathVariable Long id) {
    try {
        return Result.success(userService.getUser(id));
    } catch (BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    } catch (Exception ex) {
        return Result.fail("B000001", "系统异常");
    }
}
```

这样写会非常丑，而且重复。

有了全局异常处理后，Controller 可以保持干净：

```
@GetMapping("/user/{id}")
public Result<UserRespDTO> getUser(@PathVariable Long id) {
    return Result.success(userService.getUser(id));
}
```

业务失败时直接抛异常：

```
throw new BusinessException(ErrorCode.USER_NOT_FOUND);
```

由 `GlobalExceptionHandler` 统一处理。

---

你可以把它理解成后端项目的“统一错误出口”。

正常返回走：

```
return Result.success(data);
```

异常返回走：

```
throw new BusinessException(...);
```

最后都变成统一 JSON：

```
{
  "code": "...",
  "message": "...",
  "data": ...
}
```
