## `GlobalExceptionHandler`类的作用是：
**把 Controller/Service 里抛出来的异常统一拦住，然后转换成统一返回体 `Result` 返回给前端**。

如果没有它，接口异常时前端可能收到 Spring Boot 默认错误：

```
{
  "timestamp": "...",
  "status": 500,
  "error": "Internal Server Error",
  "path": "/api/user"
}
```

有了它之后，你可以统一返回：

```
{
  "code": "A000401",
  "message": "用户未登录",
  "data": null
}
```

---

## **`@RestControllerAdvice` 是什么？**

它可以理解成：

```
@ControllerAdvice + @ResponseBody
```

也就是说，它会增强所有 Controller，并且方法返回值会自动序列化成 JSON。

典型写法：

``` java
@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult()
                .getFieldErrors()
                .get(0)
                .getDefaultMessage();

        return Result.fail("A000400", message);
    }

    @ExceptionHandler(Throwable.class)
    public Result<Void> handleThrowable(Throwable ex) {
        log.error("系统异常", ex);
        return Result.fail("B000001", "系统执行出错");
    }
}
```

---

它的处理流程是这样的：

```
前端请求
  ↓
Controller
  ↓
Service 抛异常
  ↓
异常向上冒泡
  ↓
GlobalExceptionHandler 捕获
  ↓
转换成 Result
  ↓
返回 JSON 给前端
```

比如 Service 里：

```
public UserRespDTO getUser(Long id) {
    UserDO user = userMapper.selectById(id);
    if (user == null) {
        throw new BusinessException(ErrorCode.USER_NOT_FOUND);
    }
    return BeanUtil.toBean(user, UserRespDTO.class);
}
```

全局异常处理器捕获：

``` java
@ExceptionHandler(BusinessException.class)
public Result<Void> handleBusinessException(BusinessException ex) {
    return Result.fail(ex.getCode(), ex.getMessage());
}
```

最终前端收到：

```
{
  "code": "A000404",
  "message": "用户不存在",
  "data": null
}
```

## `@ExceptionHandler` 是用来声明“这个方法处理哪种异常”。

比如：

```
@ExceptionHandler(BusinessException.class)
```

只处理业务异常。

```
@ExceptionHandler(MethodArgumentNotValidException.class)
```

处理参数校验异常，比如 `@Valid` 校验失败。

```
@ExceptionHandler(Throwable.class)
```

兜底处理所有没被前面捕获的异常。

一般顺序上你要设计这几类：

``` java
@RestControllerAdvice
@Slf4j
public class GlobalExceptionHandler {

    /**
     * 处理业务异常
     */
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    }

    /**
     * 处理参数校验异常
     */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult()
                .getFieldErrors()
                .stream()
                .findFirst()
                .map(FieldError::getDefaultMessage)
                .orElse("请求参数错误");

        return Result.fail("A000400", message);
    }

    /**
     * 处理未知异常
     */
    @ExceptionHandler(Throwable.class)
    public Result<Void> handleThrowable(Throwable ex) {
        log.error("未知异常", ex);
        return Result.fail("B000001", "系统繁忙，请稍后再试");
    }
}
```

---

为什么要全局异常处理？

因为不想每个 Controller 都这样写：

``` java
@GetMapping("/user/{id}")
public Result<UserRespDTO> getUser(@PathVariable Long id) {
    try {
        return Result.success(userService.getUser(id));
    } catch (BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    } catch (Exception ex) {
        return Result.fail("B000001", "系统异常");
    }
}
```

这样写会非常丑，而且重复。

有了全局异常处理后，Controller 可以保持干净：

``` java
@GetMapping("/user/{id}")
public Result<UserRespDTO> getUser(@PathVariable Long id) {
    return Result.success(userService.getUser(id));
}
```

业务失败时直接抛异常：

```
throw new BusinessException(ErrorCode.USER_NOT_FOUND);
```

由 `GlobalExceptionHandler` 统一处理。

---

你可以把它理解成后端项目的“统一错误出口”。

正常返回走：

```
return Result.success(data);
```

异常返回走：

```
throw new BusinessException(...);
```

最后都变成统一 JSON：

```
{
  "code": "...",
  "message": "...",
  "data": ...
}
```

## @ExceeptionHandler

`@ExceptionHandler` 本身不是“全项目拦截器”。它能不能拦截整个项目，取决于它写在哪里。

如果写在某个 Controller 里面：

``` java
@RestController
public class UserController {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handle(BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    }
}
```

那它主要处理**当前 Controller** 里抛出来的 `BusinessException`。

**如果写在 `@RestControllerAdvice` 类里面：**

``` java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handle(BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    }
}
```

那它就可以处理**所有 Controller 调用链里抛出来的同类型异常**。

比如：

```
Controller -> Service -> Mapper
```

只要异常最终冒泡回 Controller 层，并且没有被你中途 `try-catch` 吃掉，就会被 `GlobalExceptionHandler` 捕获。

例如 Service 抛：

```
throw new BusinessException(ErrorCode.USER_NOT_FOUND);
```

Controller 不捕获：

```
@GetMapping("/user/{id}")
public Result<UserRespDTO> getUser(@PathVariable Long id) {
    return Result.success(userService.getUser(id));
}
```

那 `@RestControllerAdvice + @ExceptionHandler(BusinessException.class)` 就能统一处理。

但有几个边界你要知道：

1. 被你自己 `try-catch` 掉的异常，它拦不到

```
try {
    userService.create();
} catch (BusinessException e) {
    // 这里你已经处理了，没有继续 throw
}
```

2. 异步线程里的异常，它通常拦不到

比如你自己开线程：

```
new Thread(() -> {
    throw new BusinessException(...);
}).start();
```

这个异常不在当前 HTTP 请求链路里。

3. Filter 里某些异常，不一定会进 `@RestControllerAdvice`

因为 Filter 在 DispatcherServlet 之前执行。全局异常处理主要处理 Controller 层及其调用链里的异常。

4. 拦截器 `preHandle` 里抛异常，大多数情况下可以被 Spring MVC 异常机制处理，但具体也看异常发生阶段和配置。
    
5. 定时任务、MQ 消费者、启动初始化代码里的异常，不属于 HTTP Controller 调用链，也不会被它处理。
    

所以更完整的说法是：

**`@RestControllerAdvice` 里的 `@ExceptionHandler` 可以拦截整个 Spring MVC Controller 请求链路中抛出的指定类型异常。**

不是整个 JVM、不是所有线程、也不是所有 Filter/MQ/定时任务异常。

常见项目里这样设计就够了：

``` java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException ex) {
        return Result.fail(ex.getCode(), ex.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValidException(MethodArgumentNotValidException ex) {
        return Result.fail("A000400", "参数校验失败");
    }

    @ExceptionHandler(Throwable.class)
    public Result<Void> handleThrowable(Throwable ex) {
        return Result.fail("B000001", "系统异常");
    }
}
```

然后 Controller 和 Service 里就不用到处写 `try-catch`。业务异常直接 `throw`，统一交给它处理。
