**问题:**
错误码为什么要一个枚举继承一个接口.直接一个类,在里面定义好错误码常量和code/message的构造和get,set方法不行吗

**回答:**
可以，直接一个类当然也行。比如：

```
public class ErrorCode {
    public static final String USER_NOT_FOUND_CODE = "A000001";
    public static final String USER_NOT_FOUND_MSG = "用户不存在";
}
```

或者：

```
@Data
@AllArgsConstructor
public class ErrorCode {
    private String code;
    private String message;
}
```

这些都能跑。项目里设计成：

```
public interface IErrorCode {
    String code();
    String message();
}
```

然后：

```
public enum BaseErrorCode implements IErrorCode
```

主要是为了**规范、类型安全、可扩展**。

最核心的区别是：接口定义“错误码必须具备什么能力”，枚举定义“一组固定错误”。

比如异常类里可以这样写：

```
public AbstractException(String message, Throwable throwable, IErrorCode errorCode) {
    this.errorCode = errorCode.code();
    this.errorMessage = errorCode.message();
}
```

它接收的是 `IErrorCode`，所以不关心你传进来的是哪个错误码枚举。

以后你可以有很多错误码枚举：

```
public enum BaseErrorCode implements IErrorCode
public enum UserErrorCodeEnum implements IErrorCode
public enum OrderErrorCodeEnum implements IErrorCode
public enum PaymentErrorCodeEnum implements IErrorCode
```

然后异常统一接收：

```
throw new ClientException(UserErrorCodeEnum.USER_NOT_FOUND);
throw new ServiceException(OrderErrorCodeEnum.ORDER_CREATE_ERROR);
```

如果不用接口，异常类可能就只能依赖某一个具体类：

```
public ClientException(BaseErrorCode errorCode)
```

那以后 `UserErrorCodeEnum`、`OrderErrorCodeEnum` 就不好统一传进来了。

枚举还有一个好处：**错误码是固定集合，不允许随便 new**。

```
BaseErrorCode.CLIENT_ERROR
BaseErrorCode.SERVICE_ERROR
```

这些是有限、明确、可枚举的。

如果你用普通类：

```
new ErrorCode("xxx", "随便写")
```

那任何地方都可以临时造一个错误码，项目大了之后错误码会散掉，不利于统一管理。

再说 `get/set`。错误码一般不应该有 `set`。

错误码应该是常量，定义好以后就不变：

```
private final String code;
private final String message;
```

如果你给它加 `setCode()`、`setMessage()`，理论上运行中就能被改，这不符合“错误码常量”的语义。

所以它用枚举更合适：

```
CLIENT_ERROR("A000001", "用户端错误")
```

天然不可随意修改。

简单对比一下：

|方案|优点|问题|
|---|---|---|
|普通常量类|简单，上手快|code 和 message 容易分散，缺少类型约束|
|普通 ErrorCode 类|可以封装 code/message|可以随便 new，也可能被 set 修改|
|enum 枚举|固定集合，语义清晰|稍微多写一点代码|
|enum + IErrorCode|支持多个业务错误码枚举统一处理|抽象层多一层|

所以这个设计的重点不是“枚举继承接口很高级”，而是这句话：

**所有错误码，不管来自哪个业务模块，都必须能提供 `code()` 和 `message()`，并且都能被异常体系统一处理。**

你自己项目初期可以这样写，简单又规范：

```
public interface IErrorCode {
    String code();

    String message();
}
```

```
public enum ErrorCode implements IErrorCode {

    SUCCESS("0", "成功"),
    CLIENT_ERROR("A000001", "客户端错误"),
    UNAUTHORIZED("A000401", "用户未登录"),
    FORBIDDEN("A000403", "无访问权限"),
    SERVICE_ERROR("B000001", "系统执行出错");

    private final String code;
    private final String message;

    ErrorCode(String code, String message) {
        this.code = code;
        this.message = message;
    }

    @Override
    public String code() {
        return code;
    }

    @Override
    public String message() {
        return message;
    }
}
```

如果你的项目很小，也可以先不用接口，直接一个 `ErrorCode enum`。但我不建议用可 `set` 的普通类做错误码，因为错误码本质上应该是稳定常量。
