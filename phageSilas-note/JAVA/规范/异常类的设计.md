**问题:**
异常为什么要先声明一个抽象类,反正异常抛出的code和message可以直接定义,也就是去掉这个抽象类`AbstractException`会怎样,只保留Client,Service,Remote三个异常类

**回答:**
可以去掉 `AbstractException`，只保留：

```
ClientException
ServiceException
RemoteException
```

项目一样能跑。只是会带来一个问题：**三个异常类里会出现大量重复代码，而且全局异常处理不好统一接收。**

现在这个项目的设计大概是：

```
AbstractException extends RuntimeException
    ├── ClientException
    ├── ServiceException
    └── RemoteException
```

`AbstractException` 统一保存：

```
private final String errorCode;
private final String errorMessage;
```

并且统一从 `IErrorCode` 里取：

```
this.errorCode = errorCode.code();
this.errorMessage = errorCode.message();
```

这样三个子类只需要表达“异常类型”。

比如：

```
throw new ClientException(BaseErrorCode.CLIENT_ERROR);
throw new ServiceException(BaseErrorCode.SERVICE_ERROR);
throw new RemoteException(BaseErrorCode.REMOTE_ERROR);
```

全局异常处理器也可以统一写：

``` java
@ExceptionHandler(AbstractException.class)
public Result<Void> handle(AbstractException ex) {
    return Results.failure(ex.getErrorCode(), ex.getErrorMessage());
}
```

如果去掉 `AbstractException`，你就要么在三个类里重复写：

```
public class ClientException extends RuntimeException {
    private final String errorCode;
    private final String errorMessage;
}
```

```
public class ServiceException extends RuntimeException {
    private final String errorCode;
    private final String errorMessage;
}
```

```
public class RemoteException extends RuntimeException {
    private final String errorCode;
    private final String errorMessage;
}
```

每个类都要写字段、构造器、getter。以后想加一个字段，比如：

```
requestId
detail
args
```

三个类都要改。

要么你在全局异常处理里分开拦截：

``` java
@ExceptionHandler(ClientException.class)
public Result<Void> handleClient(ClientException ex) {}

@ExceptionHandler(ServiceException.class)
public Result<Void> handleService(ServiceException ex) {}

@ExceptionHandler(RemoteException.class)
public Result<Void> handleRemote(RemoteException ex) {}
```

这也能用，但重复。

所以 `AbstractException` 的意义是：**把三类业务异常的共同部分抽出来，让子类只负责表达分类。**

可以理解成：

```
AbstractException：我是一种业务异常，我有 code 和 message。
ClientException：我是客户端错误。
ServiceException：我是服务端错误。
RemoteException：我是远程调用错误。
```

为什么是抽象类，而不是普通类？

因为它不希望你直接这样抛：

```
throw new AbstractException(...);
```

“抽象业务异常”这个概念太泛了，真正抛出时应该明确是哪类：

```
throw new ClientException(...);
throw new ServiceException(...);
throw new RemoteException(...);
```

这能让异常语义更清楚。

不过，对你自己的项目来说，如果暂时没有远程调用，也不想搞太复杂，可以简化成两个类：

```
public class BusinessException extends RuntimeException {
    private final String code;
    private final String message;
}
```

然后所有业务异常都抛：

```
throw new BusinessException(ErrorCode.USER_NOT_FOUND);
```

等项目变大后，再拆：

```
ClientException
ServiceException
RemoteException
```

我的建议是：

```
学习项目/小型单体：
一个 BusinessException 足够。

中型项目：
BusinessException + ErrorCode enum + GlobalExceptionHandler。

大型项目/规范化项目：
AbstractException + ClientException/ServiceException/RemoteException + IErrorCode。
```

所以去掉 `AbstractException` 不会怎样，项目能运行。只是你会失去一个统一抽象层，后面异常字段、构造逻辑、全局处理都会更重复。
