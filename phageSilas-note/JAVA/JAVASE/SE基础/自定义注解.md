在 Java 中自定义注解非常简单，核心就是使用 `@interface` 关键字，并结合**元注解**来限定它的作用范围和行为。
## 介绍
### 第一步：定义注解（使用 @interface）

假设我们要定义一个用于**标记接口是否需要记录日志**的注解 `@Loggable`：

```java
import java.lang.annotation.*;

// 1. 元注解：定义作用目标（这里指只能用在类上）
@Target(ElementType.TYPE)
// 2. 元注解：定义生命周期（这里指运行时保留，以便反射读取）
@Retention(RetentionPolicy.RUNTIME)
// 3. 元注解：让该注解包含在 Javadoc 中（可选）
@Documented
public @interface Loggable {
    // 4. 定义属性（注意：这里看起来像方法，实际上是属性）
    String value() default ""; // 默认值为空字符串

    int level() default 1;     // 默认级别为 1
}
```

---

### 第二步：认识关键的元注解（必须掌握）

在定义时，最常用的是以下三个元注解：

-   **`@Target`**：限制注解可以贴在哪里。
    -   `ElementType.TYPE`（类/接口）
    -   `ElementType.METHOD`（方法）
    -   `ElementType.FIELD`（字段）
    -   `ElementType.PARAMETER`（参数）
    -   支持多个：`@Target({ElementType.METHOD, ElementType.TYPE})`
-   **`@Retention`**：限制注解保留到什么时候（**重要**）。
    -   `RetentionPolicy.SOURCE`：仅源码阶段（如 `@Override`），编译后丢失。
    -   `RetentionPolicy.CLASS`：编译时保留，JVM 加载时丢失（默认）。
    -   `RetentionPolicy.RUNTIME`：**运行时保留**，可以通过反射读取（**90% 的自定义注解都用这个**）。
-   **`@Documented`**：生成 API 文档时是否包含该注解。

---

### 第三步：注解属性的数据类型

注解支持的数据类型有限，必须是以下几种：

1.  基本类型（`int`, `double`, `boolean` 等）
2.  `String`
3.  `Class` 类型（如 `Class<?>`）
4.  枚举（`Enum`）
5.  其他注解
6.  以上类型的**数组**（例如 `String[] names()`）

> **注意**：属性可以有默认值（使用 `default` 关键字），也可以没有默认值（使用时必须赋值）。如果属性名为 `value` 且只有一个属性，使用时可以省略 `value=`。
> 
> 1. **不要在这个属性定义里加参数**：写成 `String message(String str)` 会直接报语法错误，注解属性不能有参数。
> 2.  **默认值必须是常量**：不能是 `new String(...)` 或调用方法，只能是字面量、枚举常量或 Class 常量。
> 3.  **空字符串作为默认值**：如果你想表示“没有默认消息”，通常写 `default ""`，然后在解析时判断 `isEmpty()`。


---

### 第四步：使用注解

将注解贴到目标类上：

```java
// 使用了 value 属性，level 采用默认值 1
@Loggable(value = "UserService", level = 2)
public class UserService {
    // 业务逻辑...
}

// 如果只有一个 value 属性，可以简写为 @Loggable("UserService")
```

---

### 第五步：通过反射解析注解（核心逻辑）

如果不写代码去读取，注解本身不会产生任何作用。我们通过 **Java 反射机制** 来获取注解信息并执行逻辑：

```java
import java.lang.reflect.AnnotatedElement;

public class AnnotationProcessor {
    public static void main(String[] args) {
        // 获取 UserService 的 Class 对象
        Class<UserService> clazz = UserService.class;
        
        // 判断该类是否贴了 Loggable 注解
        if (clazz.isAnnotationPresent(Loggable.class)) {
            // 获取注解实例（本质上是 JVM 生成的动态代理对象）
            Loggable loggable = clazz.getAnnotation(Loggable.class);
            
            // 读取属性值并执行逻辑
            String module = loggable.value();
            int level = loggable.level();
            
            System.out.println("正在记录日志: 模块=" + module + ", 级别=" + level);
            // 这里可以真正调用 Log4j 或 SLF4J 打印日志
        }
    }
}
// 输出结果：正在记录日志: 模块=UserService, 级别=2
```

---

### 进阶技巧：自定义注解结合 AOP（Spring 常用）

在 Spring Boot 项目中，你通常不会手动写反射代码，而是结合 **AOP（面向切面编程）** 使用。

1.  **定义注解**（同上）。
2.  **编写切面类**，使用 `@Around` 环绕通知，通过 `joinPoint.getSignature()` 获取方法上的注解，实现无侵入式的权限校验、日志打印或接口限流。

---

### 避坑指南（重点提醒）

1.  **Retention 忘了写**：默认是 `CLASS`，如果你用反射 `getAnnotation` 去拿，拿到的会是 `null`。**一定要检查是否写了 `@Retention(RetentionPolicy.RUNTIME)`**。
2.  **Target 限制不匹配**：如果你把注解定义成只能用在 `METHOD` 上，却贴在了类上，编译时会直接报错。
3.  **注解不能继承**：注解本身不支持 `extends`，但可以利用 `@Inherited` 元注解让子类继承父类的注解（仅限于类上的注解，方法上的不继承）。

## 注解是怎么触发的,对类使用的注解和对方法使用的注解,触发方式和结果又有什么区别

**注解本身永远不会“自动触发”任何逻辑，它只是一块“贴在代码上的标签”。真正“触发”动作的，是外部程序（框架、编译器或工具）主动去“读取”这块标签。**

就像二维码本身不会响，必须是**扫码枪（处理器）**去扫它，才会弹出页面。

---

### 1. 注解的触发方式（谁来“扫码”）

根据注解的 `@Retention`（生命周期），触发它的“扫码枪”分为三种：

| 触发阶段 | 扫描工具 | 典型注解 | 触发结果 |
| :--- | :--- | :--- | :--- |
| **源码期（SOURCE）** | **编译器（javac）** | `@Override`、`@SuppressWarnings` | 编译时检查语法，编译后注解消失，不产生任何字节码影响。 |
| **编译期（CLASS）** | **注解处理器（APT）** | Lombok 的 `@Data`、MapStruct | 在编译时动态生成新的 `.java` 或 `.class` 文件，**运行时根本不存在这个注解**。 |
| **运行期（RUNTIME）** | **反射（Reflection）** 或 **AOP 动态代理** | Spring 的 `@Transactional`、`@RequestMapping` | **这是最常用的方式**。JVM 启动后，框架通过反射读取注解，在方法调用前后插入逻辑。 |

> **你平时自定义的限流、日志注解，99% 都是 RUNTIME 级别**，靠 Spring AOP 在运行时触发。

---

### 2. 触发机制的本质：不是“注解触发”，而是“拦截器匹配”

既然注解是被读取的，那么**类上的注解**和**方法上的注解**在触发逻辑上，区别不在于“怎么触发”（都是反射读取），而在于**拦截器（AOP切面）的匹配范围**和**生效优先级**。

#### 区别一：切面匹配的“粒度”不同（核心区别）

-   **方法注解**：属于**细粒度精准打击**。切面会精确拦截“贴了该注解的**具体某个方法**”的执行。
-   **类注解**：属于**粗粒度批量覆盖**。切面一旦检测到类上贴了注解，通常意味着**该类的所有公共方法**都会被拦截逻辑影响。

> **举例（Spring 事务）**：
> - 方法上贴 `@Transactional`：只有这个方法有事务。
> - 类上贴 `@Transactional`：**该类下所有 `public` 方法**都会被自动注入事务逻辑。

#### 区别二：生效的“时机”不同

-   **方法注解**：在**方法执行前/后/环绕**时触发（比如限流、日志、权限校验）。
-   **类注解**：很多时候在**Bean 实例化阶段**就触发了（比如 `@Component` 让类被扫描注册到 Spring 容器），或者在类初始化时设置全局默认属性（比如类上的 `@RequestMapping("/user")` 给所有方法加上 `/user` 前缀）。

#### 区别三：优先级和覆盖规则（类级是默认，方法级是覆盖）

在 Spring 中，如果**类上**和**方法上**都贴了同一个注解（比如都有 `@Transactional`）：

-   **触发结果**：**方法上的注解会覆盖类上的注解**（方法级优先级更高）。
-   这意味着，类注解提供了一个“默认配置”，方法注解可以针对个别接口进行“特殊微调”。

---

### 3. 实战图解：框架是如何“区别对待”它们的？

以 Spring AOP 的切点表达式（Pointcut）为例，你能直观看到触发目标的差异：

```java
// 1. 拦截所有【类上】标注了 @MyAnnotation 的类中的所有方法
@Pointcut("@target(com.demo.MyAnnotation)")
public void classPointcut() {}

// 2. 拦截所有【方法上】标注了 @MyAnnotation 的单个方法
@Pointcut("@annotation(com.demo.MyAnnotation)")
public void methodPointcut() {}
```

-   如果使用 `@target`，切面会扫描所有 Bean 的 Class 对象，一旦类上有注解，该类的**所有方法**都会被代理。
-   如果使用 `@annotation`，切面只在执行具体方法时，去检查**当前这个方法**上有没有贴标签。

---

### 4. 特殊案例：类注解如何影响“非直接调用”？

这里有一个容易踩坑的点：**类注解不会自动传递给子类或实现类**，除非子类也贴了，或者使用了 `@Inherited` 元注解。

-   **父类贴了注解，子类没贴**：默认情况下，Spring 扫描子类时**不会**继承父类的类注解（事务、RequestMapping 都不会继承）。
-   **接口方法贴了注解，实现类没贴**：Spring 默认**不会**通过接口方法上的注解触发事务（必须把注解写在实现类上，或者启用 CGLIB 代理并配置参数）。

---

### 总结一句话回答你的问题：

-   **触发方式**：注解**从不主动触发**，全靠**反射/AOP 拦截器被动读取**。
-   **类注解 vs 方法注解**：
    -   **触发范围不同**：类注解影响整个类的所有方法（批量生效）；方法注解只影响单个方法（精准生效）。
    -   **触发时机不同**：类注解可能影响 Bean 的加载生命周期；方法注解只在方法调用时触发。
    -   **触发结果不同**：如果同时存在，**方法注解的配置会覆盖类注解的配置**（就近原则）。
