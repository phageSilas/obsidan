在Java并发编程中，**线程安全**（Thread Safety）是一个非常核心的概念。简单来说，它指的是：**当多个线程访问某个类（或对象、方法）时，不管运行环境采用何种调度方式或者这些线程将如何交替执行，并且在主调代码中不需要任何额外的同步或协同，这个类都能表现出正确的行为。**

换句话说，如果一段代码在单线程下运行的结果和在多线程下运行的结果完全一致，且不会出现数据错乱、丢失等预期外的情况，那它就是线程安全的。

## 一、 为什么 `String` 本身就是线程安全的？（不可变性）

像 `String` 这样的类之所以是天生线程安全的，核心原因在于它的**不可变性（Immutability）**。

- **内部实现：** 在Java中，`String` 内部使用 `final` 修饰的字符数组（Java 9 之后是 byte 数组）来保存字符串，且 `String` 类本身也被声明为 `final`，意味着它不能被继承、重写。
    
- **无状态修改：** 一旦一个 `String` 对象被创建，它的值就永远无法改变。如果你对 `String` 进行拼接、裁剪、替换等操作，它实际上并不会修改原对象，而是**创建并返回一个新的 `String` 对象**。
    
- **线程安全的本质：** 既然多个线程只能**读**这个对象，而绝对无法**修改**它，那么自然就不会出现多线程下的数据冲突问题。
    

**其他类似的天生线程安全（不可变）的类包括：**

- **基本类型的包装类：** `Integer`, `Long`, `Double`, `Boolean` 等。
    
- **数学计算类：** `BigDecimal`, `BigInteger`。
    
- **枚举类型（Enum）：** 枚举实例的创建天生是线程安全的。

## 二、 保证线程安全的常用方法与工具

如果我们要处理可变的数据或状态，就需要依靠各种并发机制来保证线程安全。Java 并发包（`java.util.concurrent`，简称 JUC）和底层关键字提供了丰富的工具：

### 1. 互斥同步（加锁）

这是最常见也最直观的保证线程安全的方式，即同一时间只允许一个线程访问共享资源。

- **`synchronized` 关键字：** Java 原生的锁机制。可以修饰方法或代码块。它是可重入的悲观锁，JVM 在底层做了大量优化（如偏向锁、轻量级锁），目前性能非常优秀，日常开发首选。
    
- **`ReentrantLock`：** JUC 包提供的显式锁。相比 `synchronized`，它提供了更灵活的控制能力，例如：尝试获取锁（`tryLock`）、可中断的获取锁、公平锁（按排队顺序获取）等。
    

### 2. 非阻塞同步（乐观锁/CAS）

加锁会导致线程阻塞和上下文切换，开销较大。非阻塞同步基于 **CAS (Compare-And-Swap)** 算法，假设没有冲突去更新数据，如果发现冲突就重试，直到成功。

- **原子类（Atomic Variables）：** 比如 `AtomicInteger`, `AtomicLong`, `AtomicReference`, `AtomicBoolean` 等。如果只是为了保证简单的数字递增或对象引用的线程安全，使用原子类比加锁高效得多。
    

### 3. 使用线程安全的数据容器

在多线程下使用普通的 `HashMap` 或 `ArrayList` 会引发严重问题（如 `HashMap` 的死循环或数据丢失）。Java 提供了专门的并发容器：

- **`ConcurrentHashMap`：** 替代 `HashMap`。通过分段锁（JDK 1.7）和 CAS+红黑树（JDK 1.8）实现了极高的并发读写性能。
    
- **`CopyOnWriteArrayList`：** 替代 `ArrayList`。它的原理是“写时复制”，每次修改操作都会复制一份底层数组，适合**读多写少**的场景。
    
- **阻塞队列（BlockingQueue）：** 比如 `ArrayBlockingQueue`, `LinkedBlockingQueue`。常用于生产者-消费者模型中，天然保证出队和入队的线程安全。
    

### 4. 线程封闭（Thread Confinement）

如果把数据封闭在各自的线程内部，不让其他线程看到，那就根本不需要同步。

- **`ThreadLocal`：** 它为每个线程都提供了一个独立的变量副本。比如在 Web 开发中，常常用 `ThreadLocal` 来保存当前请求的用户信息或数据库连接，各个线程修改自己的副本，互不干扰。
    

### 5. 保证可见性与有序性

- **`volatile` 关键字：** 它用来修饰变量，保证该变量的更新对所有线程**立即可见**，并禁止指令重排。
    
    - _注意：_ `volatile` 只能保证可见性，**不能保证复合操作（如 `i++`）的原子性**。它通常配合 CAS 操作或作为状态标记（如 `boolean flag`）来使用。
