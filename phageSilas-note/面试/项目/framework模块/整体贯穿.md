```Now I have a comprehensive understanding of the framework module. Let me organize it.
The framework module is the foundational infrastructure layer that provides cross-cutting concerns shared across all modules (bootstrap, infra-ai, mcp-server). It has 10 sub-packages:

1. cache - Redis key serializer

11. trace - Trace context (TTL-based) + annotations
12. web - Global exception handler, SSE sender, result builder
```
`framework` 模块是整个项目的**底层基础设施层**，为 `bootstrap`、`infra-ai`、`mcp-server` 等所有上层模块提供通用的横切关注点。它不包含任何业务逻辑，只提供框架级能力。

### 1. [`context/`](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/context) — 用户上下文传递

| 类 | 作用 |
|---|---|
| [UserContext](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/context/UserContext.java) | 基于 **TTL**（`TransmittableThreadLocal`）的当前用户容器，支持跨线程池透传 |
| [LoginUser](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/context/LoginUser.java) | 登录用户信息（userId、username、role、avatar） |
| [ApplicationContextHolder](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/context/ApplicationContextHolder.java) | Spring 容器持有者，用于在非 Spring 管理的类中获取 Bean |

**为什么用 TTL 而非普通 ThreadLocal**：因为 RAG 流程大量使用线程池（意图分类并行、检索并行），普通 ThreadLocal 在子线程中取不到父线程的用户信息，TTL 会自动透传。

```java
// 请求进来时设置（通常在 Filter/Interceptor 中）
UserContext.set(LoginUser.builder().userId("123").username("张三").build());

// 任何地方，包括异步线程池中都能获取
String userId = UserContext.getUserId();
```

### 4. [`idempotent/`](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/idempotent) — 幂等性控制（AOP）

提供两种粒度的幂等控制，都是基于 Redis 的声明式注解：

| 注解 | 切面 | 场景 |
|---|---|---|
| [`@IdempotentSubmit`](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/idempotent/IdempotentSubmit.java) | [IdempotentSubmitAspect](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/idempotent/IdempotentSubmitAspect.java) | **防重复提交**：Redis 分布式锁，同一用户短时间内不能重复请求同一接口 |
| [`@IdempotentConsume`](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/idempotent/IdempotentConsume.java) | [IdempotentConsumeAspect](file:///D:/IDEA-java/ragent/framework/src/main/java/com/nageoffer/ai/ragent/framework/idempotent/IdempotentConsumeAspect.java) | **防重复消费**：Lua 原子 SET NX 标记消息状态（CONSUMING → CONSUMED），消费中重复则抛异常触发 MQ 重试 |

RAGChatController 的用法：
```java
@IdempotentSubmit(key = "T(com...UserContext).getUserId()",
                  message = "当前会话处理中，请稍后再发起新的对话")
@GetMapping("/rag/v3/chat")
public SseEmitter chat(...) { ... }
```

`RagTraceContext` 用了一个很巧妙的设计——`nodeStack` 的 `copy()` 方法是**深拷贝**：

```java
// 父线程 push → 子线程继承独立副本 → 各自 push/pop 互不干扰
private static final TransmittableThreadLocal<Deque<String>> NODE_STACK = new TransmittableThreadLocal<>() {
    @Override
    public Deque<String> copy(Deque<String> parentValue) {
        return parentValue == null ? null : new ArrayDeque<>(parentValue);
    }
};
```

```
  ├── ClientException    ← 客户端错误（参数、权限），返回 4xx
```

## 一句话总结

`framework` 模块是项目的**"操作系统内核"**——它不干具体的 RAG 业务，但提供了所有模块都要用到的底层能力：

| 能力 | 实现方式 |
|---|---|
| 用户透传 | TTL 实现跨线程池上下文传递 |
| 幂等控制 | AOP 注解 + Redis 锁 / Lua 原子操作 |
| 消息队列 | RocketMQ 生产者抽象 + 事务消息 |
| 链路追踪 | TTL 透传 traceId + 节点栈 |
| 统一响应 | `Result<T>` + 全局异常拦截 |
| 分布式 ID | Redis Lua 分配 workerId + Hutool Snowflake |
| 公共约定 | ChatMessage / ChatRequest / RetrievedChunk |
