mcp-server是一个**独立的 Spring Boot 应用**，充当 MCP（Model Context Protocol）工具服务器，向 `bootstrap` 主应用暴露可被 LLM 调用的远端工具。

---

## 整体定位

```
┌─────────────────────────┐        MCP 协议          ┌──────────────────────┐
│     bootstrap (主应用)    │  ◄──────────────────►  │     mcp-server        │
│                         │   HTTP Streamable        │  (端口 9099)          │
│  McpClientToolExecutor  │   调用远程工具            │                      │
│       ↓                 │                          │  SalesMcpExecutor    │
│  McpSyncClient          │                          │  WeatherMcpExecutor  │
│       ↓                 │                          │  TicketMcpExecutor   │
│  调用 mcpServer         │                          │                      │
└─────────────────────────┘                          └──────────────────────┘
```


它是**可独立部署**的微服务，三方代码量极小——只有 5 个 Java 文件。

---

## 关键文件解析

### 1. [McpServerApplication](file:///D:/IDEA-java/ragent/mcp-server/src/main/java/com/nageoffer/ai/ragent/mcp/McpServerApplication.java) — 启动类

```java
@SpringBootApplication
public class McpServerApplication {
    public static void main(String[] args) {
        SpringApplication.run(McpServerApplication.class, args);
    }
}
```


普通 Spring Boot 启动类，监听 **9099** 端口，不依赖 `framework` 或 `infra-ai` 模块，完全独立。

### 2. [McpServerConfig](file:///D:/IDEA-java/ragent/mcp-server/src/main/java/com/nageoffer/ai/ragent/mcp/config/McpServerConfig.java) — MCP 服务端配置

这是连接 MCP SDK 和 Spring Boot 的桥梁：

```java
@Bean
public HttpServletStreamableServerTransportProvider transportProvider() {
    return HttpServletStreamableServerTransportProvider.builder().build();
}

@Bean
public ServletRegistrationBean<...> mcpServlet(...) {
    return new ServletRegistrationBean<>(transportProvider, "/mcp");  // ← 端点
}

@Bean
public McpSyncServer mcpServer(...,
        List<McpServerFeatures.SyncToolSpecification> toolSpecs) {  // ← 自动收集所有工具
    return McpServer.sync(transportProvider)
            .serverInfo("ragent-mcp-server", "0.0.1")
            .tools(toolSpecs)
            .build();
}
```


三个关键动作：
- **注册 Servlet** 到 `/mcp` 路径，处理 MCP 协议请求
- **收集所有 `SyncToolSpecification` Bean**（由各 Executor 的 `@Bean` 方法注册）→ 自动注册为可调用的工具
- **启动 `McpSyncServer`**，开始监听 MCP 请求

### 3. 三个工具执行器

每个执行器都是一个 `@Component`，通过 `@Bean` 方法向 MCP Server 注册一个工具。

| 执行器 | toolId | 功能 | 模拟数据规模 |
|---|---|---|---|
| [SalesMcpExecutor](file:///D:/IDEA-java/ragent/mcp-server/src/main/java/com/nageoffer/ai/ragent/mcp/executor/SalesMcpExecutor.java) | `sales_query` | 销售数据查询（汇总/排名/明细/趋势） | 5 大区 × 3 产品线 × 15+ 客户 × 工作日每天 3~8 单 |
| [WeatherMcpExecutor](file:///D:/IDEA-java/ragent/mcp-server/src/main/java/com/nageoffer/ai/ragent/mcp/executor/WeatherMcpExecutor.java) | `weather_query` | 天气查询（实时/预报） | 20 个城市 × 4 季节模拟 |
| [TicketMcpExecutor](file:///D:/IDEA-java/ragent/mcp-server/src/main/java/com/nageoffer/ai/ragent/mcp/executor/TicketMcpExecutor.java) | `ticket_query` | 客户工单查询（汇总/列表/统计） | 5 大区 × 4 状态 × 6 分类 × 30 天数据 |

以 `SalesMcpExecutor` 为例，看看工具的注册结构：

```java
@Component
public class SalesMcpExecutor {
    private static final String TOOL_ID = "sales_query";      // ← 工具ID，和意图节点 mcpToolId 对应

    @Bean
    public McpServerFeatures.SyncToolSpecification salesToolSpecification() {
        return new McpServerFeatures.SyncToolSpecification(
            buildTool(),                                        // ← 工具定义（参数 Schema）
            (exchange, request) -> handleCall(request)          // ← 处理函数
        );
    }

    private Tool buildTool() {
        // 构建 JSON Schema：
        //   region: string enum(华东/华南/华北/西南/西北)
        //   period: string enum(本月/上月/本季度/上季度/本年), default=本月
        //   product: string enum(企业版/专业版/基础版)
        //   salesPerson: string
        //   queryType: string enum(summary/ranking/detail/trend), default=summary
        //   limit: integer, default=10
        return Tool.builder()
                .name(TOOL_ID)
                .description("查询软件销售数据，支持按地区、时间、产品...")
                .inputSchema(inputSchema)
                .build();
    }

    private CallToolResult handleCall(CallToolRequest request) {
        // 1. 解析参数
        // 2. 生成模拟数据（按日期缓存）
        // 3. 按 queryType 输出不同格式的结果
        return successResult(formattedText);
    }
}
```


**注意**：这些数据全部是 `Random(seed)` 生成的**模拟数据**，每次同一天查询结果一致（种子基于日期+城市哈希），实现了伪真实感。实际生产环境中，`handleCall` 里替换为真实数据库查询或 API 调用即可。

## 与 `bootstrap` 主应用的协作流程

```
用户在聊天中问: "本月华东区销售数据怎么样？"
        │
        ▼ bootstrap/rag
  ① DefaultIntentClassifier → LLM 打分 → NodeScore(sales-data, 0.95)
  ② NodeScore.node.kind = MCP, node.mcpToolId = "sales_query"
  ③ RetrievalEngine.executeMcpTools()
        │
        ▼ McpClientAutoConfiguration（bootstrap 中）
  ④ McpSyncClient 连接 http://localhost:9099/mcp
     → tools/list → 发现 sales_query, weather_query, ticket_query
  ⑤ McpToolRegistry 注册: Map{ "sales_query" → McpClientToolExecutor, ... }
        │
        ▼ RetrievalEngine.executeSingleMcpTool()
  ⑥ LLMMcpParameterExtractor.extractParameters(question, tool)
     → {region: "华东", period: "本月", queryType: "summary"}
        │
        ▼ McpClientToolExecutor.execute(parameters)
  ⑦ mcpClient.callTool(new CallToolRequest("sales_query", {region: "华东", ...}))
     → HTTP POST → mcp-server:9099/mcp
        │
        ▼ mcp-server/SalesMcpExecutor.handleCall()
  ⑧ 生成模拟销售数据 → 格式化文本 →
     "【本月 销售数据汇总】\n总销售额: ¥1,234.56 万\n..."
        │
        ▼ 返回 bootstrap
  ⑨ contextFormatter.formatMcpContext() → 注入 RetrievalContext.mcpContext
  ⑩ RAGPromptService 组装 Prompt → LLM 回答
```

## 为什么设计成独立服务？

| 原因 | 说明 |
|---|---|
| **进程隔离** | MCP 工具可能调用外部系统或执行耗时操作，独立进程避免拖垮主 RAG 服务 |
| **独立扩缩容** | 工具调用量大时可单独扩容 mcp-server 实例 |
| **协议标准** | 使用 MCP 官方 SDK，如果未来增加 MCP Server，只需新增 Executor 注册 `SyncToolSpecification` 即可 |
| **热插拔** | 新增工具只需加一个 `@Component` + `@Bean`，无需改 bootstrap 代码 |

## 依赖极简

```xml
<!-- pom.xml -->
<dependency>
    <groupId>io.modelcontextprotocol.sdk</groupId>
    <artifactId>mcp</artifactId>           <!-- MCP 协议 SDK -->
</dependency>
<dependency>
    <groupId>io.modelcontextprotocol.sdk</groupId>
    <artifactId>mcp-json-jackson2</artifactId>  <!-- JSON 序列化 -->
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>  <!-- 内嵌 Tomcat + Servlet -->
</dependency>
```


只依赖 Spring Boot Web + MCP SDK，不依赖项目的 `framework` / `infra-ai` 任何模块，充分解耦。

---

**一句话总结**：`mcp-server` 是一个**极简的 MCP 工具微服务**——用标准 MCP 协议暴露 `sales_query`、`weather_query`、`ticket_query` 三个模拟工具，被 `bootstrap` 主应用的 LLM 通过 `McpSyncClient` 远程调用，实现「AI 实时获取外部数据」的能力。
