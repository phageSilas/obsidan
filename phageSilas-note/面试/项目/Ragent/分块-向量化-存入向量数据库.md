## 三、PIPELINE 模式（走流水线引擎）

### [runPipelineProcess()](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/knowledge/service/impl/KnowledgeDocumentServiceImpl.java#L335-L378)

不走直接分块，而是**委托给 IngestionEngine** 执行完整的可配置流水线：

```java
// 从对象存储读取文件字节
byte[] fileBytes = is.readAllBytes();

// 构建上下文（设置 skipIndexerWrite=true，让外层统一写向量）
IngestionContext context = IngestionContext.builder()
    .taskId(docId)
    .rawBytes(fileBytes)               // 原始字节流
    .vectorSpaceId(VectorSpaceId.builder().logicalName(collectionName).build())
    .skipIndexerWrite(true)             // ← 关键：跳过 IndexerNode 的写入
    .build();

// 执行流水线
IngestionContext result = ingestionEngine.execute(pipelineDef, context);
// result.getChunks() 已经包含分块 + embedding
```


流水线内部执行 ChunkerNode 完成分块+嵌入（逻辑与 CHUNK 模式相同），但 IndexerNode 因为 `skipIndexerWrite=true` 只做校验不写入。

## 四、共同终点：原子化持久化

### [persistChunksAndVectorsAtomically()](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/knowledge/service/impl/KnowledgeDocumentServiceImpl.java#L250-L274)

这一步是**关键的事务边界**，保证分块记录和向量数据的一致性：

```java
transactionOperations.executeWithoutResult(status -> {
    // ① 清理旧数据
    knowledgeChunkService.deleteByDocId(docId);           // 删 DB 中的旧 chunk
    vectorStoreService.deleteDocumentVectors(collectionName, docId); // 删 Milvus 中的旧向量

    // ② 写入新数据
    knowledgeChunkService.batchCreate(docId, chunks);     // 新 chunk 写入 DB
    vectorStoreService.indexDocumentChunks(collectionName, docId, chunkResults); // 新向量写入 Milvus

    // ③ 更新文档状态
    document.setStatus("success"); document.setChunkCount(n);
    documentMapper.updateById(document);
});
```

### 最终写入 Milvus： [MilvusVectorStoreService.indexDocumentChunks()](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/rag/core/vector/MilvusVectorStoreService.java#L55-L88)

```java
public void indexDocumentChunks(String collectionName, String docId, List<VectorChunk> chunks) {
    // 提取所有 embedding 并校验维度
    List<float[]> vectors = extractVectors(chunks, dim);

    // 构建 Milvus 的行数据 [{"id":"xxx", "content":"...", "metadata":{...}, "embedding":[0.1, 0.2, ...]}, ...]
    for (VectorChunk chunk : chunks) {
        JsonObject row = new JsonObject();
        row.addProperty("id", chunk.getChunkId());
        row.addProperty("content", content);
        row.add("metadata", buildMetadata(collectionName, docId, chunk));
        row.add("embedding", toJsonArray(vector));
        rows.add(row);
    }

    // 调用 Milvus SDK 批量插入
    InsertReq req = InsertReq.builder().collectionName(collectionName).data(rows).build();
    InsertResp resp = milvusClient.insert(req);  // ← 最终写入
}
```

### 关键数据载体：[VectorChunk](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/core/chunk/VectorChunk.java)

在整个链路中，`VectorChunk` 是贯穿 Extract → Chunk → Embed → Persist 的核心数据对象：

```java
public class VectorChunk {
    String chunkId;           // 唯一标识（雪花ID）
    Integer index;            // 在文档中的序号
    String content;           // 文本内容
    Map<String, Object> metadata; // 元数据
    float[] embedding;        // 向量（Chunk阶段为空，Embed阶段填充）
}
```


**向量化**就是填充 `embedding` 字段的过程——把 `content`（文本）通过 Embedding 模型转为 `float[4096]`（向量），这就是后续检索时做语义相似度计算的基础。
