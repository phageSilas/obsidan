## RAG 全链路流程

整个 RAG 对话管线的执行顺序在 `StreamChatPipeline.execute()`：

```
加载记忆 → 查询改写 → 意图分类 → 歧义引导 → 
         ↓ 核心阶段 ↓
    【检索 + 召回】→ Prompt组装 → LLM流式输出
```

---

## 检索 vs 召回 —— 本质区别

在这个项目中，**检索和召回不是同义词**，它们是 RAG 管道中**前后衔接的两个阶段**：
![[image-13.png]]


可以类比搜索引擎：**检索 = 倒排索引初筛，召回 = Learning to Rank 精排**。

---

## 阶段一：检索 (MultiChannelRetrievalEngine)

检索采用**多通道并行**架构，两个主要通道同时跑：

### 通道 1：意图定向检索 (IntentDirectedSearchChannel, 优先级最高)

```
用户问题 → LLM意图分类 → 匹配到具体知识库节点 
         → 获取该知识库的 collectionName 
         → Milvus 向量相似度搜索 → 返回 chunks
```

- 只有当意图分类置信度足够高时才启用
- 搜索范围精确到**指定知识库的 Collection**

### 通道 2：全局向量检索 (VectorGlobalSearchChannel, 优先级低)

```
用户问题 → 不做意图过滤 
         → 查询所有已启用的 KnowledgeBase → 拿到所有 collectionName
         → 并行在所有 Collection 中做向量搜索 → 返回 chunks
```

- 当意图置信度低、或无意图时作为**兜底**启用
- `CollectionParallelRetriever` 并行搜索所有 Collection

### 底层搜索调用链

```
SearchChannel → RetrieverService.retrieve(query, topK) 
              → EmbeddingService.embed(query)  // 生成查询向量
              → Milvus.search(collectionName, vector, topK)  // COSINE相似度
```

---

## 阶段二：召回 / 后处理 (PostProcessor Chain)

检索阶段返回的 chunks 合并后，依次经过后处理器链：

### 处理器 1：去重 (DeduplicationPostProcessor, order=1)

```
// 按通道优先级 + chunk ID 去重，同ID保留最高分的
Map<String, RetrievedChunk> chunkMap → 按通道优先级排序 → 去重合并
```

### 处理器 2：Rerank 重排序 (RerankPostProcessor, order=10)

```
// 用 Rerank 模型对剩余的 chunks 重新打分排序，取最终 topK
rerankService.rerank(question, chunks, topK)
```

这是**召回的核心**：向量相似度 ≠ 语义相关度，Rerank 模型（通常是 Cross-Encoder）会逐对计算 query 和 chunk 的语义匹配度，精度远高于向量余弦。

## 完整数据流示意图

```
用户问题
   │
   ├─ 查询改写（指代消解、子问题拆分）
   ├─ 意图分类（LLM对意图树叶子节点打分）
   │
   ▼
┌─────────────────────────────────────┐
│         检 索 阶 段                  │
│                                     │
│  ┌─ IntentDirectedSearch ────────┐  │
│  │  意图节点 → collectionName    │  │
│  │  → Milvus COSINE search       │  │
│  └──────── topK×3 chunks ────────┘  │
│                  ∪                   │
│  ┌─ VectorGlobalSearch ──────────┐  │
│  │  所有KB → 所有 collectionName │  │
│  │  → 并行 Milvus COSINE search  │  │
│  └──────── topK×5 chunks ────────┘  │
└─────────────────┬───────────────────┘
                  ▼  (合并后可能有 100+ chunks)
┌─────────────────────────────────────┐
│         召 回 阶 段                  │
│                                     │
│  ① DedupPostProcessor (去重)        │
│     → 100+ chunks → 60 chunks       │
│                                     │
│  ② RerankPostProcessor (重排序)     │
│     → Rerank模型逐对打分             │
│     → 精选 topK (如3条)             │
└─────────────────┬───────────────────┘
                  ▼
        最终3条精选上下文
           ↓
   Prompt组装 → LLM生成回答
```

**一句话总结**：检索是「撒网」——在向量库里用 COSINE 粗筛捞一大把；召回是「收网」——用 Rerank 模型精排后只留最相关的几条，作为 LLM 的上下文。
