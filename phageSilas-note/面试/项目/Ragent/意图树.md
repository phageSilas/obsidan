整个意图树的运转分为 **6 个阶段**：数据准备 → 问题改写 → LLM 打分 → 过滤分组 → 路由执行 → 结果整合。

### 一、意图树的数据结构

意图树是一棵**三层树**，存储在数据库 `intent_node` 表中：

```
意图树 (树形结构)
├── 集团信息化 (KB, DOMAIN)
│   ├── 人事 (KB, CATEGORY, leaf) ← 绑定 kbId + collectionName
│   ├── IT支持 (KB, CATEGORY, leaf)
│   └── 财务 (KB, CATEGORY)        ← 非叶子，不参与打分
│       └── 发票相关 (KB, TOPIC, leaf)
├── 业务系统 (KB, DOMAIN)
│   ├── OA系统 (KB, CATEGORY)
│   │   ├── 系统介绍 (KB, TOPIC, leaf)
│   │   └── 数据安全 (KB, TOPIC, leaf)
│   └── 保险系统 (KB, CATEGORY)
│       ├── 系统介绍 (KB, TOPIC, leaf)
│       ├── 架构设计 (KB, TOPIC, leaf)
│       └── 数据安全 (KB, TOPIC, leaf)
├── 销售汇总数据统计 (MCP, DOMAIN)   ← MCP 类型！
│   └── 销售数据统计 (MCP, leaf)     ← 绑定 mcpToolId="sales_query"
└── 系统交互 (SYSTEM, DOMAIN)
    ├── 欢迎与问候 (SYSTEM, leaf)
    └── 关于助手 (SYSTEM, leaf)
```


**三种节点类型**（[IntentKind](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/rag/enums/IntentKind.java)）：

| 类型 | 绑定信息 | 作用 |
|---|---|---|
| `KB` | `kbId` + `collectionName` | 走向量检索（Milvus） |
| `MCP` | `mcpToolId` + `paramPromptTemplate` | 走 MCP 工具调用 |
| `SYSTEM` | 无 | 直接 LLM 回答（问候、自我介绍） |

**关键原则**：只有 **叶子节点** 才参与意图匹配打分。中间节点（DOMAIN/CATEGORY）只做语义分组，不参与匹配。

### 二、意图树的数据来源

[DefaultIntentClassifier](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/rag/core/intent/DefaultIntentClassifier.java) 同时实现了 `IntentClassifier` 和 `IntentNodeRegistry`，每次请求时的加载链路：

```
① IntentTreeCacheManager.getIntentTreeFromCache()
   → Redis key: "ragent:intent:tree" (TTL 7天)
   → 命中：反序列化 JSON → List<IntentNode>
   → 未命中 ↓

② loadIntentTreeFromDB()
   → intentNodeMapper.selectList( WHERE deleted=0 AND enabled=1 )
   → DO → IntentNode 转换（id=code, parentId=parentCode）
   → 组装父子关系 → fillFullPath
   → 写回 Redis 缓存

③ flatten(roots)
   → 将树展平 → 提取 leafNodes（只有叶子！）
   → 构建 id2Node 映射
```


每当意图节点被增删改，会调用 `clearIntentTreeCache()` 清除 Redis 缓存，下次请求自动重新加载。

```text
系统指令: 你是一个意图分类助手，请对用户的问题进行意图打分...

请对以下意图分类进行打分，输出 JSON 数组：

- id=sales-data

  path=集团信息化 > 人事
```

**LLM 返回**：
```json
[
```

### 六、路由到不同执行分支

[RetrievalEngine.retrieve()](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/rag/core/retrieve/RetrievalEngine.java) 根据意图类型分流：

```
对于每个子问题的意图列表：

┌─ KB 意图 ─────────────────────────────────────┐
│  MultiChannelRetrievalEngine                   │
│    → VectorGlobalSearchChannel （全局向量检索） │
│    → IntentDirectedSearchChannel（定向检索）    │
│    → DeduplicationPostProcessor（去重）         │
│    → RerankPostProcessor（重排序）              │
│    → contextFormatter.formatKbContext()        │
└────────────────────────────────────────────────┘

┌─ MCP 意图 ─────────────────────────────────────┐
│  RetrievalEngine.executeMcpAndMerge()           │
│    ├── ① LLM 提取参数                          │
│    ├── ② 查找 McpToolExecutor                  │
│    ├── ③ 调用远程 MCP Server                   │
│    └── ④ contextFormatter.formatMcpContext()    │
└────────────────────────────────────────────────┘
```


#### KB 分支（和之前讲的检索流程一样）

KnowledgeBase检索

#### MCP 分支 — 详细三步走

**第1步：LLM 提取参数** — [LLMMcpParameterExtractor](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/rag/core/mcp/LLMMcpParameterExtractor.java)

```java
// RetrievalEngine.executeSingleMcpTool()
Tool tool = executor.getToolDefinition();  // 从 MCP Server 获取工具定义
String customPrompt = intentNode.getParamPromptTemplate(); // 节点配置的自定义提取模板

Map<String, Object> params = mcpParameterExtractor.extractParameters(question, tool, customPrompt);
```


给 LLM 的 Prompt 包含：工具定义（参数名、类型、必填/可选、枚举值、默认值）+ 用户问题。LLM 返回：

```json
{"time_range": "current_month", "metric": "total_sales"}
```


如果该节点配置了 `paramPromptTemplate`（如[MCP_SALES_DATA_PARAMETER_EXTRACT_PROMPT](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/rag/core/intent/IntentTreeFactory.java#L357-L419)），则使用自定义的模板，里面有更详细的参数提取规则（如相对时间 → 当前月的映射、中文数字 → 阿拉伯数字转换等）。

**第2步：查找工具执行器** — [McpToolRegistry](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/rag/core/mcp/McpToolRegistry.java)

```java
Optional<McpToolExecutor> executorOpt = mcpToolRegistry.getExecutor(toolId);
// toolId = "sales_query"
```


`McpToolRegistry` 维护了一个 `Map<String, McpToolExecutor>`，key 是 `toolId`。这些 executor 是通过 `McpClientAutoConfiguration` 在启动时从所有 MCP Server 注册的。

**第3步：调用远程 MCP Server** — [McpClientToolExecutor](file:///D:/IDEA-java/ragent/bootstrap/src/main/java/com/nageoffer/ai/ragent/rag/core/mcp/McpClientToolExecutor.java)

```java
public CallToolResult execute(Map<String, Object> parameters) {
    mcpClient.callTool(new CallToolRequest(toolDefinition.name(), args));
}
```


通过官方 MCP SDK 的 `McpSyncClient`，走标准 MCP 协议调用远端 MCP Server 暴露的工具（如数据库查询、API 调用等）。返回 `CallToolResult`，包含工具执行的结果文本。


### 完整流程图

```
用户: "销售数据统计和OA系统怎么用？"
  │
  ▼ rewriteWithSplit
["销售数据统计", "OA系统使用方法"]
  │
  ▼ classifyTargets (LLM 并行打分)
[
  SubQuestionIntent("销售数据统计", [NodeScore(sales-data, 0.95)]),    ← MCP
  SubQuestionIntent("OA系统使用方法", [NodeScore(biz-oa-intro, 0.88)]) ← KB
]
  │
  ▼ 按 kind 分流
  │
  ├─ MCP: sales-data (mcpToolId="sales_query")
  │    ① LLM 提取参数: {"time_range": "current_month"}
  │    ② McpToolRegistry.getExecutor("sales_query")
  │    ③ McpClientToolExecutor.execute(params)
  │       → mcpClient.callTool(...) → 远端MCP Server → 查询结果JSON
  │    ④ contextFormatter.formatMcpContext()
  │       → "【实时数据】销售总额：1,234,567元..."
  │
  └─ KB: biz-oa-intro (kbId + collectionName)
       ① MultiChannelRetrievalEngine → Milvus 向量检索
       ② Dedup + Rerank
       ③ contextFormatter.formatKbContext()
          → "【OA系统介绍】OA系统提供流程审批、待办、公告..."
  │
  ▼ RAGPromptService.buildStructuredMessages()
[
  system: "你是企业智能助手，根据以下证据回答...",
  history: [...对话历史...],
  user:    "【实时数据】...\n\n【知识库证据】...\n\n销售数据统计和OA系统怎么用？"
]
  │
  ▼ LLMService.streamChat() → SSE 推送给前端
```


**一句话总结**：意图树用 **LLM 一次性对所有叶子节点打分**，根据节点类型（KB / MCP / SYSTEM）自动路由到不同的执行分支——KB 走向量检索，MCP 走工具调用，SYSTEM 直接问答。MCP 路由的核心是 `mcpToolId` 字段把意图节点和远程工具执行器关联起来，参数由另一轮 LLM 调用从用户问题中自动提取。
