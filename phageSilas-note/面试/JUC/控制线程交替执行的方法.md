这是一个非常经典的并发编程面试题（通常被称为“交替打印问题”或“顺次输出问题”）。这个问题完美地展示了 `wait`、`await` 和 `park` 这三种等待机制在**锁的管理**和**唤醒精确度**上的区别。

为了实现 `ABCABCABCABCABC`（依次交替，循环5次），我们需要一个核心思想：**状态机控制**。定义一个状态位，三个线程分别对应不同的状态才能执行，执行完后修改状态，并通知下一个线程。

下面我将分别用这三种方式为你写出完整的、可直接运行的代码，并剖析它们的核心差异。

---

## 1. 使用 `Object.wait()` 和 `notifyAll()`

`wait()` 依赖于 `synchronized` 对象的 Monitor 锁。它的痛点在于**无法精确唤醒指定的线程**，所以通常只能使用 `notifyAll()` 把所有等待的线程都叫醒，让它们自己去抢锁并判断状态。
``` Java
public class WaitNotifyDemo {
    // 共享状态：0代表该A执行，1代表该B执行，2代表该C执行
    private int state = 0;
    private final Object lock = new Object();

    public void printLetter(int targetState, String letter, int nextState) {
        for (int i = 0; i < 5; i++) {
            synchronized (lock) {
                // 必须使用 while 循环来防止虚假唤醒和被错叫醒
                while (state != targetState) {
                    try {
                        lock.wait(); // 不满足条件，交出锁，去休息室等待
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                    }
                }
                // 满足条件，执行业务逻辑
                System.out.print(letter);
                // 修改状态，指定下一个该谁执行
                state = nextState;
                // 唤醒【所有】在 lock 上等待的线程
                lock.notifyAll(); 
            }
        }
    }

    public static void main(String[] args) {
        WaitNotifyDemo demo = new WaitNotifyDemo();
        new Thread(() -> demo.printLetter(0, "A", 1)).start();
        new Thread(() -> demo.printLetter(1, "B", 2)).start();
        new Thread(() -> demo.printLetter(2, "C", 0)).start();
    }
}
```

**技术点评：** 这种方式有“无谓的性能损耗”。比如A执行完后，把状态改成了1，调用 `notifyAll()`，此时B和C都会被唤醒去抢锁。如果C抢到了锁，它发现状态是1不等于2，只能无可奈何地再次 `wait()`。

## 2. 使用 `Condition.await()` 和 `signal()`

`Condition` 搭配 `ReentrantLock` 完美解决了 `wait` 无法精确唤醒的问题。我们可以创建三个不同的条件队列，A等在队列A上，B等在队列B上。A执行完后，**直接精确唤醒队列B上的线程**。
``` Java
import java.util.concurrent.locks.Condition;
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;

public class AwaitSignalDemo {
    private int state = 0; // 0=A, 1=B, 2=C
    private final Lock lock = new ReentrantLock();
    
    // 三个条件队列，实现精准控制
    private final Condition condA = lock.newCondition();
    private final Condition condB = lock.newCondition();
    private final Condition condC = lock.newCondition();

    public void printA() {
        for (int i = 0; i < 5; i++) {
            lock.lock();
            try {
                while (state != 0) condA.await();
                System.out.print("A");
                state = 1;
                condB.signal(); // 精确唤醒在 condB 上等待的线程
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                lock.unlock();
            }
        }
    }

    public void printB() {
        for (int i = 0; i < 5; i++) {
            lock.lock();
            try {
                while (state != 1) condB.await();
                System.out.print("B");
                state = 2;
                condC.signal(); // 精确唤醒在 condC 上等待的线程
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                lock.unlock();
            }
        }
    }

    public void printC() {
        for (int i = 0; i < 5; i++) {
            lock.lock();
            try {
                while (state != 2) condC.await();
                System.out.print("C");
                state = 0;
                condA.signal(); // 精确唤醒在 condA 上等待的线程
            } catch (InterruptedException e) {
                e.printStackTrace();
            } finally {
                lock.unlock();
            }
        }
    }

    public static void main(String[] args) {
        AwaitSignalDemo demo = new AwaitSignalDemo();
        new Thread(demo::printA).start();
        new Thread(demo::printB).start();
        new Thread(demo::printC).start();
    }
}
```

**技术点评：** 代码优雅，性能极佳。没有“惊群效应”，A只叫B，B只叫C，C只叫A，锁的竞争被降到了最低。

## 3. 使用 `LockSupport.park()` 和 `unpark()`

这是最底层、也最直接的玩法。`park()` 和 `unpark()` 完全不需要锁，它们通过发放和消耗“许可（Permit）”来工作。我们只需要拿到线程的引用，就能通过 `unpark(Thread)` 精确启动特定的线程。
``` Java
import java.util.concurrent.locks.LockSupport;

public class ParkUnparkDemo {
    // 必须持有线程的引用，才能精确 unpark
    static Thread tA, tB, tC;

    public static void main(String[] args) {
        tA = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                // 阻塞当前线程，等待许可
                LockSupport.park();
                System.out.print("A");
                // A执行完，给B发许可，唤醒B
                LockSupport.unpark(tB);
            }
        });

        tB = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                LockSupport.park();
                System.out.print("B");
                // B执行完，唤醒C
                LockSupport.unpark(tC);
            }
        });

        tC = new Thread(() -> {
            for (int i = 0; i < 5; i++) {
                LockSupport.park();
                System.out.print("C");
                // C执行完，唤醒A，开启下一轮循环
                LockSupport.unpark(tA);
            }
        });

        // 启动线程。此时这三个线程都会卡在 park()
        tA.start();
        tB.start();
        tC.start();

        // 延迟一小会儿确保线程都启动完毕并停在了 park() 上
        try { Thread.sleep(100); } catch (InterruptedException e) {}

        // 发动机点火：主线程给 A 发一个许可，游戏开始！
        LockSupport.unpark(tA);
    }
}
```

**技术点评：** 这种写法**极度轻量级**。不需要加锁，不需要维护状态变量（状态实际上隐式地由线程唤醒顺序决定）。这也是为什么 `LockSupport` 会成为整个 JUC 同步器底层基石的原因——指哪打哪，简单粗暴。
