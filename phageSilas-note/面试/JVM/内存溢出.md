在Java开发中，**内存溢出（Out of Memory, 简称 OOM）** 是最令人头疼但也最能考验程序员功底的线上问题。

![[image-16.png]]

我们可以把 JVM 的内存结构看作是不同的“容器”，当往容器里装的东西超过了它的最大容量，且无法再清理出空间时，就会发生溢出。下面我们分三大核心区域（堆、栈、方法区）来详细拆解：

---

## 1. 堆内存溢出 (Heap Space OOM)

堆是存放对象实例的地方，这是发生 OOM 最频繁的区域。

- **报错信息：** `java.lang.OutOfMemoryError: Java heap space`
    
- **核心原因：** 在堆中没有足够的内存为新对象分配空间，并且垃圾收集器（GC）执行后也无法腾出连续的内存。
    
- **两大经典场景（面试必分清）：**
    
    1. **内存泄漏 (Memory Leak)：** 程序中存在大量已经**不再使用**的对象，但因为它们被某些长生命周期的 GC Root（如静态集合类 `HashMap`、`List` 或 `ThreadLocal`）死死引用着，导致 GC 无法回收它们。久而久之，垃圾越堆越多，最终撑爆堆内存。
        
    2. **内存溢出 (Memory Overflow / 数据量过大)：** 内存里存活的对象确实都是业务需要的，但是**瞬间的数据量太大了**。比如：一次性从数据库里 `select *` 查出了 200 万条数据；或者高并发下，每个线程都创建了占用大量内存的大对象。物理内存确实不够用了。
        
- **排查方案：**
    
    通常会在启动参数中加上 `-XX:+HeapDumpOnOutOfMemoryError`。当发生 OOM 时，JVM 会自动导出一份 `.hprof` 堆快照文件。然后使用 MAT (Memory Analyzer Tool) 或 VisualVM 打开它，查看占用内存最大的对象是谁，并追溯它的 GC Root 引用链。
    

---

## 2. 栈内存溢出 (Stack Overflow / Thread OOM)

栈是线程运行方法的地方。这里的溢出分为两种完全不同的表现形式：

- **表现一：栈深度超限**
    
    - **报错信息：** `java.lang.StackOverflowError` (注意：这实际上是一个 Error，通常不叫 OOM，但属于栈溢出范畴)。
        
    - **核心原因：** 线程请求的栈深度大于 JVM 允许的最大深度。简单来说，就是**方法调用层级太深了**，把栈帧塞满了。
        
    - **经典场景：** **无限递归**（方法自己调用自己，且没有正确的退出条件），或者两个对象在 `toString()` 方法中互相调用导致循环解析。
        
- **表现二：线程数超限**
    
    - **报错信息：** `java.lang.OutOfMemoryError: unable to create new native thread`
        
    - **核心原因：** 系统的物理内存是固定的，分配给堆和方法区后，剩下的就是给栈的。每个线程都有自己独立的栈空间（如默认 1MB）。如果程序疯狂创建线程，剩下的物理内存不足以再为新线程分配栈空间了，就会报这个错。
        
    - **经典场景：** 线程池配置失误，或者代码中有死循环不断 `new Thread().start()`。

## 3. 方法区 / 元空间溢出 (Metaspace OOM)

方法区（在 Java 8 之后被称为**元空间 Metaspace**）主要存放的是类的信息（Class 元数据）、常量、静态变量等。

- **报错信息：** `java.lang.OutOfMemoryError: Metaspace` （在 Java 7 及以前，报错是 `java.lang.OutOfMemoryError: PermGen space` 即永久代溢出）。
    
- **核心原因：** JVM 运行期间**动态生成并加载了太多的类**，导致存放类模板信息的元空间被撑爆。
    
- **经典场景：**
    
    1. **动态代理的滥用：** 比如重度使用 CGLib 或 ASM 字节码技术，在运行时动态生成了大量的代理类。Spring AOP 就是基于动态代理的，如果配置不当生成了海量的不同代理类，就会撑爆元空间。
        
    2. **JSP 页面过多：** （老旧项目）JSP 第一次运行会被编译成 Java Servlet 类，如果 JSP 极多，也会导致类加载过多。
        
    3. **热部署频繁：** 在开发环境中频繁热更新代码，旧的类加载器和类没有被及时卸载，新的类又不断加进来。
        
- **注意点：** Java 8 的元空间使用的是**本地内存 (Native Memory)**，而不是 JVM 堆内存。如果不通过 `-XX:MaxMetaspaceSize` 限制它的大小，它理论上会一直吃掉操作系统的物理内存，直到系统崩溃。
