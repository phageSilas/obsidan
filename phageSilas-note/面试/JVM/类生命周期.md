# 概述
Java虚拟机（JVM）中的类生命周期，是指一个Java类从被加载到内存中开始，直到被卸载出内存为止的整个过程。这个机制是Java实现“一次编写，到处运行”以及动态扩展功能的基础。

类在JVM中的生命周期严格遵循特定的顺序，主要包含**7个阶段**。其中最核心的三个大步是：**加载（Loading）**、**链接（Linking）** 和**初始化（Initialization）**。


## 1. 加载（Loading）

这是类生命周期的起点。在这个阶段，JVM主要完成三件核心工作：

- **获取二进制字节流**：通过类的全限定名（如 `java.lang.String`）获取定义该类的 `.class` 文件的二进制流。这个流可以来自本地磁盘、网络下载、ZIP/JAR包，甚至是在运行时动态计算生成（如动态代理）。
    
- **构建运行时数据结构**：将这个字节流所代表的静态存储结构，转化为方法区（Method Area）中 JVM 能够识别的运行时数据结构。
    
- **生成Class对象**：在Java堆内存中生成一个代表这个类的 `java.lang.Class` 对象，作为程序在方法区访问该类各种数据的入口。
    

## 2. 链接（Linking）

链接阶段负责将Java类的二进制代码合并到JVM的运行状态中，它又被细分为三个子阶段：

- **验证（Verification）**
    
    - **目的**：确保 `.class` 文件的字节流中包含的信息符合当前虚拟机的要求，并且不会危害虚拟机自身的安全。
        
    - **内容**：包括文件格式验证（如魔数 `0xCAFEBABE`）、元数据验证、字节码逻辑验证和符号引用验证。
        
- **准备（Preparation）**
    
    - **目的**：为类的**静态变量**（被 `static` 修饰的变量）分配内存，并将其初始化为**默认零值**。
![[image.png]]

        
    - **注意**：这里赋的是系统默认值（例如 `int` 为 `0`，`boolean` 为 `false`，对象引用为 `null`），而不是代码中程序员赋予的实际值。_（例外：如果变量是被 `static final` 修饰的常量，在这个阶段就会直接被赋值为代码中指定的值）。_
        
- **解析（Resolution）**
    
    - **目的**：将常量池内的**符号引用**替换为**直接引用**。
        
    - **解释**：符号引用只是一组描述目标的字符串（比如方法名、类名）；直接引用则是直接指向内存目标地址的指针、相对偏移量或句柄。
        

## 3. 初始化（Initialization）

这是类加载过程的最后一步，也是真正开始执行类中定义的Java程序代码的阶段。

- **动作**：JVM 会执行类构造器 `<clinit>()` 方法。这个方法是由编译器自动收集类中的所有**静态变量的赋值动作**和静态语句块（`static {}`）合并产生的。
    ![[image-1.png]]
- **触发时机**：JVM 严格规定了只有在“主动使用”类的时候才会触发初始化。例如：遇到 `new` 实例化对象、读取或设置一个静态字段、调用一个静态方法、或者使用反射对类进行调用时。

### 一、 类的初始化阶段与执行优先级

在Java中，代码的执行顺序严格遵循“从静态到非静态，从父类到子类，从代码块到构造器”的原则。

我们可以将类中的代码分为两大阵营：**类级别（静态）** 和 **实例级别（非静态）**。

#### 1. 静态代码阵营 (类级别)

- **包含成员**：静态变量（`static` 修饰的变量）和静态代码块（`static {}`）。
    
- **执行时机**：在**类加载的初始化阶段**执行。这发生在类第一次被“主动使用”时（例如：调用类的静态方法、访问静态字段、使用 `new` 关键字实例化对象、或是作为程序入口的 `main` 方法所在的类）。
    
- **执行次数**：伴随类的生命周期，**只会执行一次**。
    
- **内部优先级**：按照代码在源文件中**从上到下**的顺序依次执行。
    
### 2. 实例代码阵营 (对象级别)

- **包含成员**：实例变量（非静态变量）、构造代码块（`{}`，也叫实例代码块）和构造方法（如 `public Test1(){}`）。
    
- **执行时机**：在每次使用 `new` 关键字**创建类的实例（对象）时**执行。
    
- **执行次数**：每次 `new` 一个对象，就会执行一次。
    
- **内部优先级**：
    
    1. 实例变量赋值和**构造代码块**（这两者按代码从上到下的顺序执行）。
        
    2. **构造方法**（必须等构造代码块执行完毕后，最后执行）。
        
#### 💡 终极执行顺序总结（含继承关系）

如果存在父子类继承关系，完整的执行顺序（优先级从高到低）如下：

1. **父类**的静态变量 / 静态代码块
    
2. **子类**的静态变量 / 静态代码块
    
3. **父类**的实例变量 / 构造代码块
    
4. **父类**的构造方法
    
5. **子类**的实例变量 / 构造代码块
    
6. **子类**的构造方法

### 二、 解析你的代码题

基于上面的理论，我们来一步步拆解你提供的代码：
``` Java
public class Test1 {
    public static void main(String[] args) {
        System.out.println("A");
        new Test1();
        new Test1();
    }

    public Test1(){
        System.out.println("B");  // 构造方法
    }

    {
        System.out.println("C");  // 构造代码块 (实例代码块)
    }

    static {
        System.out.println("D");  // 静态代码块
    }
}
```

**执行流程推演：**

1. **类加载与初始化**：当 JVM 准备执行 `main` 方法时，首先需要加载并初始化 `Test1` 类。
    
    - 触发**静态代码块**执行。
        
    - **输出：`D`**
        
2. **进入 `main` 方法**：类初始化完成后，开始执行 `main` 方法内的逻辑。
    
    - 执行第一行代码：`System.out.println("A");`
        
    - **输出：`A`**
        
3. **第一次实例化对象**：执行第一个 `new Test1();`。
    
    - 类已经被加载过了，所以静态代码块不再执行。
        
    - 触发实例初始化。优先执行**构造代码块**。
        
    - **输出：`C`**
        
    - 接着执行**构造方法**。
        
    - **输出：`B`**
        
4. **第二次实例化对象**：执行第二个 `new Test1();`。
    
    - 同样触发实例初始化，重复上述对象创建流程。
        
    - 优先执行**构造代码块**。
        
    - **输出：`C`**
        
    - 接着执行**构造方法**。
        
    - **输出：`B`**

> **💡 核心对比：准备阶段 vs 初始化阶段**
> 
> 为了更直观地理解这两个阶段的区别，请参考下表：
> 
> |**代码声明**|**准备（Preparation）阶段**|**初始化（Initialization）阶段**|
> |---|---|---|
> |`public static int value = 123;`|`value = 0` _(分配内存并赋零值)_|`value = 123` _(执行代码中的赋值)_|
> |`public static final int MAX = 100;`|`MAX = 100` _(常量直接解析赋值)_|`MAX = 100` _(不发生变化)_|

### 4. 使用（Using）

当类初始化完成后，类就处于可使用的状态了。在这个阶段，开发者可以通过代码实例化对象（分配堆内存）、调用类中的静态或实例方法、访问字段等。此时，JVM 正常执行程序中的业务逻辑。

### 5. 卸载（Unloading）

当一个类在程序运行期间不再被需要时，它可能会被垃圾回收器（GC）从方法区中卸载。不过，要卸载一个类，必须同时满足以下**三个极其苛刻的条件**：

1. **实例全无**：该类的所有实例都已经被回收，Java堆中不存在该类的任何对象。
    
2. **加载器死亡**：加载该类的 `ClassLoader` 已经被回收。这通常只有在自定义类加载器的场景下才容易发生，JDK自带的核心类加载器（如 Bootstrap）通常不会被回收。
    
3. **毫无引用**：该类对应的 `java.lang.Class` 对象没有在任何地方被引用，意味着你无法在任何地方通过反射再次访问该类。
