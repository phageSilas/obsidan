**考勤记录页“部门筛选”后端改造说明**

当前前端“考勤记录”页的部门筛选是按 `departmentId` 精确查询，用户需要手填部门 ID，体验比较差。  
我们准备把前端改成“按部门名称搜索并选择部门”，但**考勤记录主查询接口仍然按 `departmentId` 精确过滤**，这样后端主业务逻辑基本不用动。

## 一、目标

实现效果：

- 前端不再让用户输入部门 ID
- 用户输入部门名称关键字，例如“研发”“测试”
- 前端展示匹配部门下拉列表
- 用户选择某个部门后，前端拿到该部门 `id`
- 查询考勤记录时，仍然调用现有接口，并传 `departmentId`

所以这次后端改造重点不是改考勤记录查询逻辑，而是提供一个**支持按部门名称模糊搜索的部门列表接口**

---

## 二、推荐方案

### 方案原则

- `考勤记录` 接口继续保留现有 `departmentId` 查询参数，不改主查询逻辑
- 新增或复用 `部门查询接口`，支持 `deptName` 模糊搜索
- 前端先查部门候选列表，再把选中的 `departmentId` 传给考勤记录接口

---

## 三、后端需要提供的能力

### 1. 部门列表接口支持名称模糊查询

建议复用现有部门接口，如果已有类似接口更好；如果没有，就补一个支持 `deptName` 查询条件的接口。

建议接口形态例如：

```
GET /api/v1/depts?deptName=研发&pageNum=1&pageSize=20
```

或如果你们已有统一组织接口，也可以沿用现有路径。

### 2. 返回字段最少需要

前端做搜索下拉，最少只需要：

- `id`
- `deptName`

如果还有这些字段也可以一起返回：

- `parentId`
- `status`
- `leader`
- `deptCode`

但不是必需。

示例返回：

```
{
  "code": 20000,
  "message": "success",
  "data": {
    "records": [
      {
        "id": 2,
        "deptName": "接口测试研发部"
      },
      {
        "id": 18,
        "deptName": "联调-弹性研发组"
      }
    ],
    "total": 2,
    "pageNum": 1,
    "pageSize": 20
  }
}
```

---

## 四、考勤记录接口是否需要改

### 不强制改

当前考勤记录接口如果已经支持：

- `groupId`
- `yearMonth / dateStart / dateEnd`
- `keyword`
- `departmentId`
- `status`

那这部分**可以不改**。

前端最终还是会传：

```
departmentId=2
```

所以考勤记录页的部门筛选逻辑仍然是：

- 前端按名称找部门
- 用户选中部门
- 前端把所选部门 `id` 传给现有考勤记录接口

### 当前后端逻辑可继续保留

比如你们现在如果是这种逻辑：

```
if (queryDTO.getDepartmentId() != null 
    && !queryDTO.getDepartmentId().equals(employee.getDeptId())) {
    return false;
}
```

这一段可以继续保留，不需要改成 `deptName like`。

---

## 五、建议后端确认的细节

希望后端同学确认以下几点：

### 1. 是否已有部门名称模糊查询接口

如果已有，就直接给前端可用接口路径和参数名即可。

### 2. 模糊匹配字段

建议按：

- `deptName like %keyword%`

即可。

### 3. 是否只返回启用中的部门

建议只返回有效、可选部门，例如：

- `status = 1`
- `isDeleted = 0`

### 4. 是否需要数据权限限制

如果系统有部门数据权限，建议搜索接口也走同样权限范围，避免前端能搜到无权部门。

### 5. 分页大小

前端搜索下拉一般一次取 10~20 条就够，避免返回太多。

---

## 六、为什么推荐这个方案

相比直接把考勤记录接口改成“按部门名称模糊查”，这个方案优点更明显：

- 不破坏现有考勤记录主查询逻辑
- 风险最低
- 前端体验好，不需要记部门 ID
- 名称重复或相似时，用户可以明确选中某个部门
- 后端职责清晰
    - 部门接口负责“找部门”
    - 考勤记录接口负责“按部门ID查记录”
