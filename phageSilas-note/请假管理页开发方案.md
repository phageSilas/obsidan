
## 摘要
目标是把左侧菜单里的 `请假申请` 改成 `请假管理`，并将 `/attendance/leave` 从占位页开发成面向 `管理员 / HR / 部门主管` 的请假管理界面。

已确认的产品方向：

- `HR / 管理员`：可见全部部门员工请假
- `部门主管`：只看本部门员工请假
- 页面定位：**管理页**
  - 去掉余额区
  - 去掉“提交请假”按钮
  - 只保留筛选区 + 请假记录列表
- 审批处理方式：**推荐跳审批详情页处理**
  - 本页只做筛选、查看、跟踪状态
  - 点击记录进入现有审批详情页，在审批中心完成通过/驳回

## 关键改动
### 1. 菜单与路由命名调整
把前端中考勤菜单下的：

- `请假申请`

统一改名为：

- `请假管理`

需要同步修改的位置：

- `.umirc.ts` 路由 name
- `src/constants/menu.ts`
- `src/components/AppShell/routeMeta.tsx`
- 页面标题、副标题文案

路径保持不变：

- `/attendance/leave`

这样可以避免影响已有菜单结构和权限挂载。

### 2. 页面职责重构
当前 [index.tsx](/D:/IDEA-java/HRMS/frontend/hrms-frontend-umi/src/pages/attendance/leave/index.tsx) 还是占位页。  
新页面只保留两块：

#### 顶部筛选区
筛选项固定为：

- 月份下拉 / 月份选择器
- 部门下拉
  - `HR / 管理员` 可见
  - `部门主管` 不显示该筛选项
- 员工姓名模糊搜索框
- 状态筛选下拉
  - 草稿
  - 审批中
  - 已通过
  - 已拒绝
  - 已撤回
- 查询按钮
- 重置按钮

#### 下方请假记录列表
记录列表展示字段建议固定为：

- 员工姓名
- 工号
- 部门
- 请假类型
- 开始时间
- 结束时间
- 请假天数
- 请假事由
- 审批状态
- 审批人/当前节点
- 申请时间
- 操作

操作列只保留：

- `查看审批`
- `去处理`
- `撤回`（仅申请人可撤回，若你希望管理页不做撤回，可在实现时隐藏）

本页不展示：

- 假期余额
- 提交请假按钮
- 审批规则说明卡
- 个人申请入口

### 3. 前端数据来源与接口规划
当前现成接口里只有：

- 个人请假：
  - `/api/v1/leave`
  - `/api/v1/leave/list`
  - `/api/v1/leave/{id}/cancel`
- 通用审批：
  - `/api/v1/approval/tasks/pending`
  - `/api/v1/approval/tasks/history`
  - `/api/v1/approval/{id}`

但没有“按部门/月份/员工筛选的全员请假管理列表”专用接口。  
因此需要新增一个后端管理接口，前端页面围绕它实现。

建议新增前端服务方法：

- `getAttendanceLeaveManageList(params)`

建议返回分页结构：

- `PageResult<AttendanceLeaveManageItem>`

前端新类型建议：

- `AttendanceLeaveManageQuery`
- `AttendanceLeaveManageItem`

字段建议：

- `id`
- `employeeId`
- `employeeName`
- `employeeNo`
- `deptId`
- `deptName`
- `leaveType`
- `leaveTypeDesc`
- `startTime`
- `endTime`
- `totalDays`
- `leaveReason`
- `approvalStatus`
- `approvalStatusDesc`
- `approvalInstanceId`
- `currentNodeName`
- `currentApproverName`
- `createTime`

### 4. 权限与筛选规则
前端只做轻量显示控制，最终以后端权限为准。

#### HR / 管理员
- 可见部门下拉
- 默认部门为空，表示全部部门
- 可查看所有员工请假

#### 部门主管
- 不显示部门下拉
- 默认只查 `currentUser.deptId`
- 员工搜索仅在本部门范围内生效

角色判断沿用当前前端用户信息：

- `roleCode`
- `deptId`

推荐继续使用：
- `ADMIN`
- `HR`
- `MANAGER`

### 5. 审批动作接入方式
你已确认采用“跳审批详情页处理”，因此本页不直接嵌审批按钮流转。

操作列规则建议：

- `approvalInstanceId` 存在时：
  - 显示 `查看审批`
  - 跳 `/approval/detail/${approvalInstanceId}`
- 若当前用户是当前审批人，按钮文案可显示为：
  - `去处理`
- 若只是查看历史状态：
  - `查看审批`

也就是说：
- 本页是管理列表
- 审批动作仍由现有审批详情页承接

### 6. 页面刷新与持久化
沿用你们前面已稳定的“显式加载 + 页面切回刷新”模式：

- 首屏加载：
  - `loadLeaveManageList()`
  - 若 HR，则同时 `loadDepartments()`
- 页面切到别处再切回来：
  - 重新加载列表
  - 重新加载部门列表（HR）
- 筛选条件持久化到 `sessionStorage`
  - `yearMonth`
  - `deptId`
  - `keyword`
  - `approvalStatus`
  - `pageNum`
  - `pageSize`

### 7. 需要后端新增的能力
因为当前没有管理列表接口，本次后端建议新增：

- `GET /api/v1/attendance/leaves`

查询参数建议：

- `yearMonth?: string`
- `deptId?: Long`
- `keyword?: string`
- `approvalStatus?: Integer`
- `pageNum`
- `pageSize`

权限规则建议：

- `HR / ADMIN`：全量
- `MANAGER`：仅本部门
- 其他角色：无权限访问

后端列表查询建议直接从 `hr_leave_request` 联合员工信息和审批实例信息组装，返回前端需要的管理视图字段，不让前端自己拼审批状态。

## 测试场景
- 左侧菜单项已从“请假申请”改成“请假管理”。
- 进入 `/attendance/leave` 后，不再显示占位页。
- 页面中不显示余额卡、不显示提交请假按钮。
- `HR / 管理员` 进入时可见部门筛选下拉，并默认查询全部部门。
- `部门主管` 进入时不显示部门下拉，只显示本部门员工请假。
- 按月份筛选后，请假记录按该月刷新。
- 按员工姓名模糊搜索后，列表正确过滤。
- 按审批状态筛选后，列表正确过滤。
- 点击 `查看审批 / 去处理` 能跳到现有审批详情页。
- 页面切换后再切回来，筛选条件可恢复，列表重新从后端获取。
- 无数据时，列表显示明确空态。

## 假设
- 本次开发包含前后端，不是只做前端壳页面。
- 请假管理页不承担“发起请假”职责，只承担“查看与处理管理”职责。
- 审批通过/驳回继续复用现有审批中心，不在请假管理页内直接做审批按钮流转。
- 当前角色判断仍以 `roleCode + deptId` 为前端轻量依据，最终权限以后端接口校验为准。
