大家好,接下来由我讲解本次前端系分,本次项目是由前端框架是用umi,然后配合react,typescript实现的,ui大部分有ant design提供
项目9个模块的页面实现分别对应pages目录下的几个文件夹,并且像api调用,工具函数之类的服务均有对应的文件夹,

**权限模块**的会根据登录时用户的权限决定他们能看到什么,权限字段是前后端共同约定的,登录后会把后端返回的权限字段放入全局状态,之后的渲染路由都会先判断权限是否符合再执行操作

**组织架构**和**员工档案**和**入转调离**三个模块都是增删改查,根据后端返回的数据渲染对应的界面即可

接着说**考勤管理**模块,这个模块主要的设计就是打卡界面由 React 的 `useState` 和 `useEffect` 定时器实现当前时间的每秒刷新,然后个人打卡信息界面的日历视图有Ant Design的Calendar 日历组件展示,其次考勤统计中的折线图、饼图、柱状图之类的各种图由AntV G2 实现,根据后端返回的数据集合进行渲染,(增长率的数据是根据数据库种的信息进行计算的,使用到的箭头是Ant Design 图标库里的箭头)

然后是**薪资管理**模块,他的设计和考勤管理差不多,统计图由AntV G2Plot或者Ant Design Charts实现,不过其中有一些字段脱敏的机制,例如无薪资明细权限时将实发工资显示为 `****.**`，银行卡号只保留前四后四位,不过脱敏的实现很简单,一般就是直接截取
字符串,然后用星号代替,二次验证后再显示就行(是通过usestate, React 重新渲染页面实现的),然后在这个脱敏机制在登陆界面等各种隐私界面都有使用

**审批中心**  的横向审批流程使用 Ant Design 的 Steps 组件实现，纵向审批历史使用 Timeline 组件实现，用于展示每个节点的处理人、处理时间、审批意见和状态。审批人操作同意或拒绝后，前端调用审批接口，后端推进流程，前端重新拉取详情数据并刷新 Steps 和 Timeline。

**个人中心**模块也以增删改查为主,根据后端返回的数据渲染对应的界面即可,打卡统计,薪资统计等统计图则和考勤管理模块的差不多,由antv实现,


最后是**ai模块** ,
--ai助手常态会议悬浮球的形式,显示显示在大部分界面,其置顶显示是把悬浮球做成全局组件，挂在整个应用 Layout 最外层。只要当前页面不是登录页、工资条详情等隐私页面(隐私页面如登录页、工资条详情页则通过路径白名单/黑名单控制不渲染该组件)，它就一直渲染在页面最上层。
--置顶显示靠 CSS 的position: fixed固定定位和z-index: 9999：层级很高，显示在普通页面内容之上,
--点击悬浮球展开是通过react的useState维护一个状态变量,点击悬浮球后重新渲染大小,
--用户长期不点击悬浮球,则小球就像360的悬浮球一样会"闲置收起”或“半隐藏吸边",这个长期也是和打卡的实时时间一样,由useState和useEffect维护一个计时器,半隐藏是css的一个样式(`transform: translateX`)实现,
--AI 助手展开后显示的推荐问题由前端推荐问题池或后端推荐接口提供。前端在聊天窗打开时触发一次推荐问题生成逻辑，根据当前路由、用户角色或通用问题池随机抽取 3 条问题，
点击推荐问题后发生什么
有两种设计。
第一种：只填入输入框：
```
function handleAsk(question: string) {
  setInputValue(question);
}
```
用户还要再点发送。

第二种：点击后直接发送：
```
function handleAsk(question: string) {
  sendMessage(question);
}
```

--知识库点击上传文件后弹出的本地文件选择器,由浏览器调用操作系统原生能力实现，前端不直接绘制该窗口。前端通过 Ant Design Upload 组件或原生 `input type="file"` 触发文件选择，浏览器弹出 Windows 文件选择窗口。用户选中文件后，浏览器将文件封装为 File 对象交给前端，前端再通过 `multipart/form-data` 请求上传到后端。前端可以控制文件类型、是否多选和上传逻辑，但不能完全自定义系统文件选择器的界面样式。
