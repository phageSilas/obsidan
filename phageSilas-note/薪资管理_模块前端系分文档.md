# 1. 需求背景

本模块来源于 HRMS（人资管理系统）薪资管理后端系分，目标是将薪资账套、员工薪资档案、月度薪资核算、异常处理、财务审批、工资条查看和薪资成本可视化前端化，替代 Excel 模板与手工算薪流程。

前端侧需要面向 HR、财务、员工三类角色提供不同能力：HR 维护薪资账套、员工薪资档案、创建薪资批次并处理异常；财务查看汇总、审批薪资批次并确认发放；员工完成二次验证后查看本人已发放工资条和个人薪资趋势。

# 2. 详细设计

## 2.1 前端迭代目标

本次前端迭代实现薪资管理模块核心页面与操作闭环：

* 薪资账套：账套列表、新增、编辑、启停、删除、工资项目维护。
* 员工薪资档案：员工薪资档案查询、设置、调薪历史、未设置档案员工列表。
* 月度薪资核算：创建批次、触发核算、预览薪资明细、异常处理、提交审批、确认发放。
* 工资条：员工二次验证后查看本人工资条，展示收入项、扣款项、应发、应扣、实发和近 6 月趋势。
* 可视化看板：薪资成本趋势、部门薪资分布、薪资构成占比、薪资变动分布、异常汇总。
* 安全与审计：涉薪信息按角色控制字段可见性，关键操作增加二次确认、埋点和审计入口。

### 2.2.2 薪资账套表单与工资项目页

##### UI&交互

页面路径建议：`/salary/templates/new`、`/salary/templates/:id/edit`

表单分为账套基础信息、适用范围、工资项目三块。工资项目使用可编辑表格维护，支持新增行、删除行、排序、启停和公式输入。

* 新增调用 `POST /api/v1/salary/templates`，编辑调用 `PUT /api/v1/salary/templates/{id}`。

* 工资项目编码在账套内不允许重复，前端先做本地唯一性校验，最终以后端校验为准。
* 金额和公式本期仅维护配置，不在前端执行薪资计算。

### 2.2.4 薪资批次列表页

##### UI&交互

页面路径建议：`/salary/batches`

页面用于 HR 创建和管理月度薪资批次。支持按薪资月份、批次状态、范围查询。批次状态以流程节点展示：草稿、计算中、待确认、审批中、已通过、已发放、已驳回。

##### 前端逻辑

* 页面初始化调用 `GET /api/v1/salary/batches`。
* 创建批次调用 `POST /api/v1/salary/batches`，创建成功后进入批次详情页。
* 批次状态为 `DRAFT` 时可触发核算。
* 批次状态为 `PENDING_CONFIRM` 时可查看预览、处理异常、提交审批。
* 批次状态为 `APPROVED` 时可确认发放。
* 状态变更类操作均需二次确认，并在按钮 loading 期间禁止重复点击。

# 5. 其他

## 5.1 风险评估

| 风险点 | 影响 | 前端应对 |
| --- | --- | --- |
| 涉薪数据泄露 | 造成严重安全风险 | 金额字段按权限脱敏，离开工资条页清理敏感状态 |
| 工资条二次验证失败率高 | 员工无法查看工资条 | 明确错误提示，支持重新验证，限制重复提交 |
| 薪资批次重复操作 | 导致重复计算或状态错乱 | 状态按钮 loading、防重复点击、二次确认 |
| 阻断异常未处理就提交审批 | 财务审批数据不准确 | 前端根据异常汇总禁用提交审批按钮 |
| 金额格式不一致 | 算薪预览和工资条展示不可信 | 前端统一金额格式化，保留 2 位小数 |
| 图表数据量较大 | 页面卡顿或渲染失败 | 图表懒加载，失败降级为空状态 |

## 5.2 稳定性保障

* 薪资账套、薪资档案、批次状态变更、异常处理等关键操作统一使用 loading 和防重复提交。
* 所有金额展示统一走格式化工具，不在前端执行薪资计算公式。
* 工资条二次验证成功后再拉取明细，明细不写入本地持久化存储。
* 列表接口失败时保留已有查询条件，不清空页面上下文。
* 批次提交审批前强校验阻断异常数量，避免无效提交。
* 可视化接口失败不阻断批次详情、工资条等主流程。
