我已经看到一个关键事实了：后端当前分页 VO 里还没有你原型图要求的 `scopeName`、`effectiveDate` 这类前端友好字段，更多是原始的 `scopeType/scopeValue/items`。我再把范围类型规范、实体字段和是否已有“启停/删除/复制”接口查清楚，这样我们能明确哪些能本次直接做，哪些需要后端补口。


我已经把后端能力边界摸出来了，里面有两个会直接影响方案的点需要先跟你锁一下，不然实现时就得替你做产品取舍了：

- 后端当前 `pageTemplates` 查询只支持 `templateName` 和 `status`，**没有 `scope` 查询条件**
- 后端当前分页 VO 里有 `scopeType / scopeValue / items / itemCount / status`，但**没有原型图里的 `scopeName` 和 `effectiveDate` 字段**

这两个点都会影响我们这版“薪资账套”到底是纯前端先落地，还是要先等后端补字段/筛选能力。


我又发现一个会影响抽屉配置的重要差异：原型图右侧“适用范围类型”有 `部门 / 员工 / 职级`，但后端当前 `scopeType` 只规范化支持 `ALL / DEPT / EMPLOYEE`，**没有 `JOB_LEVEL/LEVEL` 这类职级范围**。如果不先锁这个点，前端抽屉里该不该出现“职级”就会变成实现时临时拍板。
