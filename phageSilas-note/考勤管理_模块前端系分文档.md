# 1. 需求背景

本模块来源于 HRMS（人资管理系统）考勤管理后端系分，目标是将考勤规则配置、网页端打卡、补卡申请、请假申请、假期余额、月度统计和可视化看板前端化，替代纸质签到与 Excel 统计流程。

前端侧需要为员工、部门主管、HR 提供不同权限下的操作入口：员工可完成打卡、查看个人考勤、提交补卡和请假；主管和 HR 可查询权限范围内的考勤记录、请假记录、补卡记录和统计报表；HR 可维护考勤组、工作日和成员范围，为薪资核算模块提供稳定的数据入口。

# 2. 详细设计

## 2.1 前端迭代目标

本次前端迭代实现考勤管理模块的核心页面和操作闭环：

* 考勤规则配置：考勤组列表、新增、编辑、启停、删除、成员范围维护、工作日配置。
* 员工打卡：当前登录员工网页端打卡、定位授权、IP/GPS 校验提示、当日打卡结果展示。
* 个人考勤：个人打卡日历、补卡申请、补卡记录、请假申请、请假记录、假期余额查询。
* 管理查询：HR / 主管按权限查询打卡记录、请假记录、补卡记录和部门统计。
* 统计看板：个人月度统计、部门月度统计、考勤可视化数据展示，并为薪资核算入口保留汇总查询口径。

### 2.2.1 考勤组列表页

##### UI&交互


页面路径建议：`/attendance/groups`

页面用于 HR 维护考勤组。列表支持按考勤组名称、启停状态筛选，支持新增、编辑、启停、删除和进入成员 / 工作日配置。

##### 前端逻辑

* 页面初始化调用 `GET /api/v1/attendance/groups`，按分页参数拉取考勤组列表。
* 搜索条件变化后重置到第一页查询。
* 启停操作调用 `PATCH /api/v1/attendance/groups/{id}/status`，成功后刷新当前页。
* 删除操作需二次确认，调用 `DELETE /api/v1/attendance/groups/{id}`，成功后刷新当前页。
* 列表状态字段由前端字典映射：`1` 展示为启用，`0` 展示为禁用。
* 班次类型由前端枚举映射：`FIXED` 固定班，`FLEXIBLE` 弹性班，`SCHEDULED` 排班制。

### 2.2.2 考勤组表单页

##### UI&交互

页面路径建议：`/attendance/groups/new`、`/attendance/groups/:id/edit`

表单分为基础规则、班次时间、打卡范围、补卡限制和成员范围五个区域。新增页提交后默认返回列表；编辑页进入时先查询详情并回显。

##### 前端逻辑

* 新增调用 `POST /api/v1/attendance/groups`，编辑调用 `PUT /api/v1/attendance/groups/{id}`。
* 班次类型为弹性班时展示弹性最早 / 最晚打卡时间。

* GPS 范围建议通过经纬度 + 半径表单维护，提交前组装为后端约定字段。
* 成员范围支持部门、职位、员工三类，入参使用 `memberList`，元素包含 `memberType`、`memberId`。

### 2.2.4 员工打卡页

##### UI&交互

页面路径建议：`/attendance/clock`

页面展示当前日期、当前时间、所属考勤组、上班 / 下班打卡状态、定位授权状态和打卡按钮。员工点击打卡时前端获取定位与设备信息并提交后端。

##### 前端逻辑

* 页面进入后调用 `GET /api/v1/attendance/records/my-calendar` 查询当日打卡状态。
* 点击打卡前获取浏览器定位：`navigator.geolocation`，用户拒绝定位时仍允许提交，但需提示“定位未授权，将仅使用 IP 校验，可能导致打卡失败”。
* 客户端 IP 原则上由网关透传；如后端要求前端传递，则使用后端提供的取 IP 方案。
* 打卡提交 `POST /api/v1/attendance/clock`，根据响应 `clockStatus` 展示成功状态。
* 失败场景统一展示后端错误文案，如“未配置考勤组，请联系 HR”“今日非工作日”“不在打卡范围”。

### 2.2.6 补卡申请与补卡记录页

### 2.2.7 请假申请与请假记录页

##### UI&交互

## 5.1 风险评估

| 风险点 | 影响 | 前端应对 |
| --- | --- | --- |
| 浏览器定位授权失败 | 员工无法通过 GPS 校验 | 明确提示授权方式，并允许仅走 IP 校验后由后端判定 |
| IP 获取口径不一致 | 打卡范围校验失败 | 与网关 / 后端确认真实 IP 透传字段，前端不自行伪造 |

| 考勤组配置错误 | 大范围员工打卡异常 | 保存前强化必填校验，启停 / 删除使用二次确认 |
| 统计生成耗时较长 | 看板数据延迟 | 生成操作显示异步处理中状态，避免重复点击 |

## 5.2 稳定性保障

* 打卡、请假、补卡主流程按钮提交时增加 loading 和防重复提交。
* 所有分页列表保留查询条件和页码，接口失败时不清空已有数据。
* 图表数据为空时展示空状态，不阻断页面其他模块展示。
* 前端统一通过请求拦截器处理登录失效、权限不足和通用错误提示。
* 涉及 GPS、附件、审批等外部能力的页面提供明确失败提示和重试入口。
